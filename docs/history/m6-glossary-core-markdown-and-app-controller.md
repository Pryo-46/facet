### レビューが見つけた実バグ（すべて修正済み。記録として残す）

**M6 で最も価値が出たのはレビューである。** 過去のマイルストーンでは実機確認が最後の網だったが、今回は次の5件がコードレビュー段階で捕まった。うち3件は**ミューテーション（実装をわざと壊してテストが落ちるか見る）**によって発見・裏取りされている。

1. **【Critical】自己書き込み除外のテストが、壊しても落ちなかった**（`src/core/app-controller.test.ts`）: このプロジェクトで最も守るべき不変条件（自動保存が書いた内容を自分で外部変更として検知しない）の唯一のテストが `not.toContain('toast')` しか見ていなかった。ところが**この機構が壊れたときの実症状はトーストではなく二択ダイアログである**——検知時点で `hasUnsaved()` が true なので必ず `ask` に倒れ、トーストは1件も出ない。つまり「壊れた状態」と「正しい状態」を区別できないテストだった。レビュアーが `attachSaver` の write を `writeAndRecord` から `io.write` へ変えても49件全緑であることを実証した。**症状を取り違えたテストは、無いテストより危険である**（緑が保証に見える）
2. **【Important】二択の回答待ち中にそのファイルを削除すると、ウィンドウが永久に閉じられなくなる**（`src/core/app-controller.ts` の `deleteFile`）: `pendingAsk` を落とす経路5つのうち `deleteFile` だけが抜けていた。ダイアログは `dropModal` で取り下げるのに信号は残るので、`requestClose()` が「存在しないダイアログ」を待ち続ける。トーストは出るが、そこで案内されるダイアログはもう無い。脱出は「フォルダを開く」を押すことだけで、ユーザーには推測不能。**Task 5（削除）と Task 6（外部変更）の継ぎ目**であり、単体では両方とも正しい
3. **【Important】`cell()` のバックスラッシュ未エスケープ**（`src/modules/glossary/markdown.ts`）: `|` だけをエスケープしていたため、`a\|b` が `a\\|b` になり、GFM では「リテラルの `\`」＋「非エスケープの列区切り」と読まれて表が割れる。定義・備考は自由記述欄なので Windows パスや正規表現で現実的に踏む
4. **【Minor だが要件違反】`## ${title}` が無エスケープ**: `title` はスキーマ上ただの `string` なので、外部が書いた改行入りの値で **h1 が混入**する。「h1 は使わない」は M6 の明示要件
5. **【計画の漏れ】fixture 移設が2ファイル取り残されていた**: `sample-project/glossary.json` を読むテストは4つあったのに、計画の Files 欄が2つしか挙げていなかった。**`sample-project/` を退避して `npm test` 全体を回す**という検証手順があったから見つかった（対象を絞って回していたら見逃していた）

### 実機確認の位置づけの変化（次回への申し送り）

M5 までは「実機確認が最後の網」だったが、M6 では**自動テストが網になり、実機確認は前提の確認になった**。ただし次の項目は**依然として実機でしか確かめられない**ので、この層に触るときは実機確認を省かないこと:

- **モーダル表示中に背景のボタンが押せないこと。** `canExport`（Markdown 出力ボタン）は二択ダイアログ表示中も論理的には true のままで、押せないことは **Radix `AlertDialog` の `modal` 既定と `FocusScope` が背景操作を構造的に阻止する**ことにのみ依存している。既存のヘッダボタン（「元に戻す」「フォルダを開く」）も同じ前提に乗っており、**とくに「フォルダを開く」が押せてしまうと `closeCurrentFile` が未保存編集を持つ履歴を捨てる**。ここは多くの安全性がぶら下がる載荷点なので、モーダル基盤（`src/components/ui/alert-dialog.tsx`、`ConfirmDialog`、`ChoiceDialog`）に手を入れたら必ず実機で押して確かめる
- クリップボードに実際に貼れる内容が入るか（テストはプラグイン呼び出しへの委譲までしか見ていない）
- 保存ダイアログの拡張子フィルタが強制なのか（OS 依存）
- リロード後に Rust 側の watcher が leak しないこと（`beforeunload` での `unwatch` を足したが、開発中の HMR でしか起きないので自動テストに載せられない）

### 実装で確定した事項（計画の前提に昇格）

- **額縁の副作用は `src/core/app-controller.ts` が持つ。`App.tsx` は「コントローラを state に繋ぐ」だけ**（420 行）。I/O は `AppIo`、UI 反映は `AppHost` として注入する。**コアは React も Tauri も知らない**ので、副作用の順序を node 環境のテストで固定できる。2本目のツールが来ても額縁の配線を書き直す必要は無い
- **コントローラは状態をクロージャ変数で持ち、`AppHost` に getter を1つも生やさない**: `host.setFiles` 等は**表示の複製**であって判断材料ではない。M5 の Critical 2件は「レンダごとに代入する ref では過去の値を凍結できない」「表示側の値を判断に使った」ことが原因だったが、クロージャ変数なら代入が同期で確定するため、この種の誤りが構造的に起きない。**唯一の getter は `getEditingData()`** で、これは「履歴は App が持つ」という所有権の帰結（読む側はいずれもユーザー操作起点＝レンダ後なので、`historyRef` の更新とズレる経路は無い）。**この非対称を「揃えて」getter を増やさないこと**
- **移した先のテストは「実装を壊すと落ちるか」で検証する**: 上記の Critical はこの手順でしか見つからない。**新しく順序を固定するテストを書いたら、対応する実装を1行壊して落ちることを必ず確認する**。M6 ではレビュアーと実装者の双方がこれを実行し、複数の「守っていないテスト」を摘出した
- **すべての分岐にテストを書けるわけではない**: `knownDisk.clear()`（`openFolder`）と `knownDisk.retain()`（`rescan`）は、無効化しても観測可能な振る舞いが変わらないことを2者が独立に確認した——`openFolder` は `clear()` 直後に全パスを `set` し直し、`planExternalChange` は `prev`（＝一覧）から `prevPaths` を作るため、台帳は正しさの判定に構造的に接続していない（メモリ肥大化防止のハウスキーピング）。**black-box で守れないものに「守っていないテスト」を足さない**という判断を採った
- **バナーは種別を持つ**（`BannerKind = 'io' | 'save' | 'scan' | 'watch'`）: 単一スロットだった頃は「フォルダの監視を開始できません」（**継続する状態**）が次の任意の I/O 成功で消え、逆に再走査の失敗は成功しても消えなかった。`watch` は監視が張れたときだけ、`scan` は再走査が成功したときだけ、`io` は次の操作が成功したときに消す。**バナー＝いま続いている状態、トースト＝起きた出来事**（M5 で確定）を、種別ごとの消去条件として具体化したもの
- **`.md` 書き出しは台帳（`knownDisk`）に載せない**: 走査対象は `.json` だけなので、記録しても次の再走査の `retain` で落ちる死に記録になる。同じ理由で、プロジェクトフォルダ内へ書き出しても監視は反応しない（差分ゼロ）。**ただしこれは保存ダイアログの拡張子フィルタに依存する**——`.json` を打てた場合は自分の書き込みが外部変更として検知される（実害は二択ダイアログが出るまで）
- **出力ロジックは純関数**（規約5）。額縁がクリップボードコピーと `.md` 書き出しの両方に同じ関数を使うため、モジュール側がファイルやクリップボードに触ってはならない
- **種別グループの順序はスキーマの enum から実行時に導出する**（`glossarySchema.$defs.term.properties.kind.enum`）。ハードコードすると enum 改訂時に静かにずれる。**enum に無い `kind` の用語も落とさず末尾のグループに出す**——出力から黙って消える用語を作らないため
- **テストファイルは M6 まで型チェックされていなかった**: `tsconfig.test.json` が `tsconfig.app.json` を `extends` しており、`include` は上書きしていたが `exclude`（テストファイル）を継承していたため、include したファイルが exclude で全部落ちていた。M1 の申し送り「テストは `tsconfig.test.json` で型チェックする」がそのまま空振りしていた。`"exclude": []` で塞いだ。**`extends` した設定に `include` だけ書いても効かない**
- **`sample-project/` は動作確認の遊び場に戻した**: 正規形のバイト一致テストの fixture は `src/core/__fixtures__/glossary.canonical.json` にある。**この fixture は触ってはいけない**（`canonical.test.ts` にその旨を書いた）。動作確認は**リポジトリ外の空フォルダ**で行う

### いつでもよいが、忘れると実害化する残件

M6 で新たに見つかったもの。**レビューの記録は作業ワークスペースと一緒に消えるので、残すならここに書く**——本節が唯一の恒久的な記録である。

- **interleaving を要する3分岐にテストが無い**（`src/core/app-controller.ts`）: `rescan` の `switchingFolder > 0` ガード（フォルダ切替中に届いた旧フォルダのイベントが新しい一覧を上書きする）、`rescan` の `token !== scanSeq || projectDir !== dir` ガード（遅れて着地した古い走査結果が新しい一覧を上書きする）、`handleSelectedGone` の `selectSeq++`（進行中の `selectFile` が着地して消えたファイルを選び直す）。**コントローラは I/O を注入しているので `io.scan` に手動 Promise を挟めば書ける**。この層に触るときの宿題
- **`ensureFileOfType` は将来のインライン登録から呼ぶと二択と競合する**（`src/core/app-controller.ts`）: 内部で `rescan()` を回すので、`ask` が出た直後に `selectFile` で選択を移してしまい、回答が「選択が変わったため書き戻しませんでした」に倒れる。今日は「用語集を作る」ボタンが空状態（未選択時）にしか出ないので到達不能だが、**インライン登録を実装した時点で踏む**（M4 の申し送りの `ensureFileOfType` に関する申し送りと併せて読むこと）
- **`exportMarkdown` は保存ダイアログを開いている間のデータ変化を拾わない**: `doc.data` はダイアログを出す前のスナップショット。ネイティブダイアログが開いている数秒〜数分の間に外部変更の取り込みが走ると、書き出される Markdown は取り込み前の内容になる。書き出し先は新規パスなのでデータ喪失にはならない
- **`dropModal` の対象に `delete:<path>` が入っていない**: 外部でファイルが消えた後に古い削除確認を確定すると、`trashFile` が失敗して「ファイルを削除できませんでした」が出る。JSDoc は実態に合わせて直したが、機構としては残っている
- **`### ${kindLabel(kind)}` の見出しがエスケープを通らない**: 現状 `kind` はスキーマ検証済みの enum 値しか来ないので実害は無い（enum 拡張時に生値が見出しへ出る経路としてのみ残る）
- **`currentDocument()` の「未選択」分岐を明示的に踏むテストが無い**（「編集中データなし」分岐と観測が重なる）
- **`closeCurrentFile` のバナークリアのコメントから「M2 の申し送り」への参照が落ちた**（過去障害の手がかり）。`deleteFile` と `file-ops.ts` の `trashFile` の JSDoc は「切り離しは trash の前に」の説明を重複して持つ（片方だけ更新されると食い違う）
- **`tsconfig.test.json` の説明を `"//"` キーで書いている**が、`extends` 元の `tsconfig.app.json` は JSONC の `/* */` を使っており不統一

M2〜M5 の申し送りからの継続（M6 では手を付けていない）: **編集1打鍵ごとに全ファイルの `checkConsistency` を再実行している**／**定義セル・種別セルが `mark(index, field)` を参照していない**／**`@testing-library/user-event` が未使用**／**`resolveCommand` の細かい非対称**（macOS の `Ctrl+Backspace` / `Alt+Shift+↑↓`）／**`CellInput` の `caretAtStart` / `caretAtEnd` は collapsed なキャレットのみ true**／**`file-naming.ts` の `ILLEGAL` が Windows の予約デバイス名を弾かない**（ユーザー入力が届く経路は M6 でも増えていない）／**`FileList` の行ボタンのアクセシブル名が固定**／**`ConfirmDialog.dom.test.tsx` が見出しを `getByText` で引いている**／**`move_to_trash` が同期コマンドなので削除中にウィンドウが固まる**／**`FLUSH_MAX_ROUNDS` の打ち切りパスに直接テストが無い**／**`fileExists` に専用の単体テストが無い**／**`ChoiceDialog` のオーバーレイクリックのテストが無い**／**選択中でないファイルが外部変更でスキーマ違反になっても「外部の変更を読み込みました」と出る**

※ M5 の申し送りの残件「`switchingFolderRef` が boolean でカウンタでない」は M6 で解消（カウンタにした）。M5 の申し送りの「モーダルキューに `dropModal` / `clearModals` を足す」も対応した（`dropModal` は実装、`clearModals` は「引数を取らず `[]` を返すだけで何も守らない」ため関数ごと廃し `setModals([])` に統合）。M5 の申し送りの「`ioError` の単一スロットの意味論」「`ensureGlossary` の早期 return が無言」「`overwriteWithMine` の無言 return と `saveError` 未クリア」「`askExternalChange` が古いトーストを消さない」「ページのリロードで watcher が leak する」「`sample-project/` は fixture」もすべて M6 で解消した。
