## 何を作ったか

- **仮説の文言を3つに割った。** `title`（何を作るか。旧 `text`）／`detail`（どう作るか。新設）／`value`（なぜ効くと考えるか。新設）。m4 の画面は `title` だけを出す（旧 `text` の位置に）。`detail` / `value` はデータとして入るが画面には出さない（決定C・Global Constraints）。
- **「聞きたいこと」（`asks`）を新設した。** レビューで何をもって支持・棄却を判定するかを先に書いておく問いの配列。`id` を持つ（`feedbacks` から参照されるため）。
- **FB を `pendingNotes`（文字列配列）から `feedbacks`（属性つきオブジェクト配列）へ拡張した。** `askId`（どの問いへの答えか。`null` 可）／`text`／`by`（誰の発言か）／`sentiment`（`like` / `concern` / `question` / `note` の4語）／`date` を持つ。旧 `text` の位置に `feedbacks[].text` を出す。
- **課題の旗を1種（`deferred`）から2種（`deferred` / `resolved`）にした。** `toggleDeferral` を `toggleIssueEvent(data, index, kind, today?)` に一般化し、同じ種別を押すと外れる・別の種別を押すと差し替わる（消してから足す）・イベントが無ければ足す、の3規則で入り切りする（決定D）。抑制（`suppressedIssueIds`）はどちらの旗でも効く。帯の別枠は種別ごとに独立したチップ（`見送り N` ／ `解決 N`）になった。
- **`rationale` と `promoteNote`（「根拠へ移す」）を廃止した。** 展開パネルの「由来」の節と「根拠へ」ボタンは無くなった（決定は引き継ぎ書。ボタンの reveal 機構ごと消えた）。
- **イベントに表示用の `date`（`YYYY-MM-DD`）を持たせた。** `src/core/today.ts` に `todayString(now: Date = new Date())` を新設し、`commands.ts` の追記系関数が末尾の省略可能な引数として受け取る（`newId` と同じ形。決定A）。空文字は許さない。
- **「未判断」を「FB待ち」に改名し、数える単位を問い（ask）にした。** `HypothesisQuestions.feedback` は `boolean` ではなく `number`（FB を待っている問いの件数）。文言が空の問いは数えない（着手前の論点3）。**行き先（`listOpenTargets`）は仮説につき1つしか出さない**——m4 には問いを1件ずつ指せる DOM のセルが無いため、チップの数（問いの数）が巡回列の長さ（仮説の数）を上回りうる非対称が生まれた（決定B。`open-targets.ts` のコメントとテストに明記）。
- **`detail` / `value` / `asks` の編集コマンドは作らなかった。** 例外は `title` と `feedbacks[].text`（旧 `text` / `pendingNotes[i]` の置き換え）だけ（決定C）。m5 が画面と一緒に決める。
- **`resolved` を新規に付ける動線は作らなかった。** 読める（バッジ・チップ・アクセシブル名がすべて `kind` から引く）が、立っていない旗を新規に立てるボタンは無い（決定E）。m5 のマージまでの間だけの状態である。
- **スキーマの `properties` 記載順を正規形のキー順にした。** 仮説は `id, issueId, title, detail, value, asks, feedbacks, events`（決定G）。
- **登録 Skill・お手本・配布ガイドを追随させた。** `.claude/skills/issue-tree-register/`（スキーマと `derive.ts` はバイト一致コピー。`issue-tree-write.mjs` と `SKILL.md` は手で追随。`new-id.mjs` に `--prefix ask` を追加）、`sample-project/課題ツリー.json`（書き直し。`asks` / `feedbacks` / `resolved` の実例を含む）、`src/core/reading-guide.md`（配布物 `README-for-AI.md` の原本）。
