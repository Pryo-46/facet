## 実装で確定した事項

### モジュール規約8（任意）として `tableExport` を新設した

表形式コピーは既存の規約5（`OutputProfile`）に乗らなかった。あちらは「Markdown 文字列を返す純関数」＋ `.md` 書き出しを前提にしており、表形式コピーはこの前提を3点とも壊す——出力が **TSV と HTML の2つ**で1本の文字列に収まらない、**`.md` 書き出しに意味が無い**（ファイル出力そのものを作らないと決めた。表は「今見ているものを別の場所へ持っていく」一時的な動線であって、成果物としてリポジトリに残すものではない。成果物を残す口は既存の「Markdown を書き出す」が持っている）、そして**設定（No 列・番号形式・親のくり返し・未定義の表示）を引数に取る**。押し込むと `toMarkdown` という名前が嘘になる。**規約7（`ClipboardExchange`。Miro 交換）を別枠にしたのと同じ判断**であり、`ToolModule` に任意スロット `tableExport?: TableExport<TData>` を足した。**宣言しないツールの規約の点数は増えない**——額縁はスロットの有無だけを見てボタンの活性を決め、ツールの `type` を名指ししない。宣言したのは用語集・エラーカタログ・ロジックツリーの3本で、シーケンス・課題ツリーは宣言しない。

クリップボードへの書き込みは既存の `copyHtmlToClipboard(html, altText)` をそのまま使った（Miro 交換で既に通っている経路）。`altText` に TSV を渡すことで、Excel・スプレッドシートは HTML を、メモ帳・Slack・AI の入力欄は TSV を受け取る。

### 設計段階の `subsetByIds` 案を実装計画の途中で撤回した

**最初の設計スペック（`e6ed0ce`）は「額縁がデータを先に間引いてから出力関数へ渡す」形を書いていた**——`ToolModule` に `subsetByIds?: (data: TData, ids: ReadonlySet<string>) => TData` を持たせ、額縁が `subsetByIds(doc.data, ids)` の結果を `toMarkdown` / `toTable` に渡す案。**これは誤りだった。** エラーカタログの No はデータ配列の位置（`index + 1`）で、画面も絞り込み中に元の No を出している（`ErrorCatalogEditor.tsx:453` のコメント「No は編集対象ではない。データ配列の位置なので絞り込んでも動かない」）。額縁が先に間引くと、間引いた後の配列の位置から No が **1 から振り直され**、画面の No と出力の No が食い違う——`error-catalog/markdown.ts` の No の JSDoc が「口頭で指すための目印として使えない」と警告している、まさにその壊れ方そのものになる。

**間引きと採番は同じ場所（出力関数の内側）に置くしかない。** 計画コミット `88df693`（「表形式コピーの実装計画を書き、スペックの No の欠陥を直す」）で設計スペックを書き直し、`subsetByIds` を撤回して `toMarkdown` / `toTable` に任意引数 `visible?: VisibleRows` を足す形に改めた。**任意なので、絞り込みを持たないツール（ロジックツリー・シーケンス・課題ツリー）の出力関数は1文字も変わっていない**——実際に手を入れたのは用語集・エラーカタログの `toMarkdown` と、今回新設する3本の `toTable` だけである。

`VisibleRows = ReadonlySet<string> | null`（null は絞り込みなし＝全件）を報告する `onVisibleIds?: (ids: VisibleRows, total: number) => void` は `EditorProps` の任意コールバックとして足した。**ID で切るのが要点**——報告は `useEffect` を経由するので1フレーム古くなりうるが、index（添字）で切ると行を削除した直後の古い添字が別の行を指し間違った内容が黙って出る。ID なら消えた ID は一致せず落ちるだけで、間違った行の内容が出ることは原理的にない（最悪でも行が1本欠ける）。

### Markdown コピーの振る舞いを変え、書き出しは変えなかった

上の `visible` 引数は、表形式コピーだけでなく既存の「Markdown をコピー」にも通した。**結果として、クリップボードコピー（表形式・Markdown とも）は画面の絞り込みに追従するようになり、「Markdown を書き出す」だけは全件のまま変えていない。**

理由は口の性質が違うから。クリップボードは「今見ているものを別の場所へ持っていく」一時的な動線だが、ファイル書き出しは「成果物を残す」永続的な動線であり、絞り込んだままの `.md` は**一見完全な成果物の顔で Git に残る**。後から見て「絞り込み中だった」とはどこにも記録されない。今回いちばん侵襲的な変更であり、コピー完了のトーストを件数入り（「表をクリップボードにコピーしました（42 件中 3 件）」）に変えて、絞り込んだまま貼って一部しか渡っていない事故に気づけるようにした。ロジックツリーのように件数を報告しないツールは、数え方を説明せずに数字を出すと誤読されるため件数を付けない。

### 各ツールの表

- **用語集**: 列は画面のエディタに出ている並びそのまま（No / 用語 / 種別 / 定義 / 別名 / 備考）。種別は Markdown 出力では `###` の見出しへ逃がしているが、表には見出しが使えないので列に戻した。
- **エラーカタログ**: 列は `profile.fields` をそのまま使い、`markdownFields()`（`resolutionLevel` を落とす関数）は使わない——落とす理由（グルーピング軸が h3 見出しになる）が表には無いため。`variants` は既存の `PROFILES` から導出し、列セットの定義を増やさなかった。
- **ロジックツリー**: 列は `[No] / 第1階層 / 第2階層 / …`（列数は木の最大深さ）、行は葉ノードごとに1行。走査順は既存の Markdown 出力と同じ `buildTree` の行きがけ順に揃えた——同じデータから2つの出力が違う順で出ると後から必ず疑われるため。

## Esc が完全に無反応だった件

Task 9 の実装（`de445d9`）は `<AlertDialog open={props.open}>` に `onOpenChange` を渡していなかった。Radix の制御モードでは `onOpenChange` が無いと Esc が no-op になる——ダイアログは閉じず `onCancel` も呼ばれない。**同時に `KeyContext.modalOpen` がアプリ側の Esc ショートカットを止める**ので、利用者は Esc でも外側のショートカットでも閉じられず手詰まりになる。

レビューで Important として指摘され（Ruling R7）、`ConfirmDialog` と同じ `onOpenChange` → `onCancel` の配線に直した（`3c0bb2b`）。**この修正で、`AlertDialogAction` に元々書かれていた `preventDefault` が初めて実際に効き始めた**——Task 9 の最初の実装時点では `AlertDialogAction`（内部実装は `AlertDialogCancel` と同じ `Dialog.Close`）の `onClick` に `event.preventDefault()` は既に書いてあったが、コード中のコメント自身が「このダイアログには `onOpenChange` を渡していないので実害は無いが、経路を `copy()` 一本にするため念のため止めておく」と述べていた。`onOpenChange` を配線した瞬間、[コピー] を押すたびに `onOpenChange(false)` も発火して `onCancel` まで呼ばれる二重発火が現実の経路になり、`preventDefault` がそれを止める役を初めて負った——`ConfirmDialog` が M4 で踏んだ罠（`AlertDialogAction` と `AlertDialogCancel` はどちらも `Dialog.Close` なので、確認ボタンを押しても内部の close が発火する）と同じ形である。

## 階層番号の区切りを `-` から `_` へ変えた（人間の指摘）

**実装が全部終わり、最終レビューも通り、マージ直前になってから人間が見つけた。** テストもレビューも通り抜けた欠陥である。

`1-1-1` を Excel や Google スプレッドシートに貼ると **2001/1/1 に化ける。** 両者とも貼り付けたセルに型推論をかけるため。しかも3階層以上に限った話ではなく、**`1-3` のような2階層の葉も 3月1日 になる**——浅い木でも踏む。

**RFC 4180 の引用（`"…"`）では止まらない。** あれは区切り文字を守るための仕組みで、貼り先の型推論には一切効かない。`table-tsv.ts` のエスケープが正しく働いていても、この問題は素通りする。

区切りを **`_` に変えた**（`logic-tree/table.ts` の `NUMBER_SEPARATOR`）。`.` は選べない——ロケールによっては `1.1.1` が日付として解釈される。`_` はどのロケールでも数値にも日付にもならない、唯一の確実な選択肢だった。通し番号（`serial`）は素の整数なのでこの問題を持たない。

**なぜ誰も気づかなかったか。** 単体テストが見ているのは**文字列の形**だけで、貼り先が何をするかは見ていない。設計スペック §8 の実機確認チェックリストにも「Excel に貼ってセルが分かれること」はあったが、**「貼った値が別の型に化けないこと」は無かった**——チェックリストが「壊れ方の想像力」の分だけしか広がらない、という限界がそのまま出た形である。

**教訓**: 貼り先が型推論をする経路（表計算・CSV・JSON パーサ）へ値を渡す出力は、**文字列として正しいことと、貼った先で同じ意味に読まれることが別問題**である。前者しかテストできないなら、後者は実機確認の項目として明示的に立てる。

## フォローアップ: 押せないボタンの理由を読めるようにする（人間の指摘）

**完成した機能を人間が実機で触ったあとの指摘。** 額縁に並ぶ5つの出力ボタン（Markdown をコピー／書き出す・表形式でコピー・Miro へコピー／から取り込む）は、**開いているツールによって使えるものが変わる**にもかかわらず、**今どれが使えるのか・なぜ押せないのかが画面から読み取れない**——ブラウザ標準の `disabled` に `disabled:opacity-50` を足しただけの見た目だったため。

**`disabled` を捨てた理由がこのフォローアップの核心。** `disabled` はブラウザがポインタイベントを丸ごと落とすため、`title` によるツールチップが**そもそも発火しない**——押せない理由を説明できたはずの唯一の経路が、`disabled` 自身によって塞がれていた。そこで `src/components/ToolbarButton.tsx` という共通の土台を新設し、`disabled` 属性の代わりに `aria-disabled="true"` を立てつつ `onClick` 自身をガードする形に変えた。ポインタイベントを殺さないので、ホバーで `title` が読める。フォーカスも `disabled` と違って外れないので、キーボードでも辿り着ける。

見た目の一段沈める表現には `text-ink-faint` / `border-rule-muted` を使い、**`opacity` は使っていない**——`src/styles/conventions.test.ts`「役割トークンに透過を掛けていない」の言う「一段薄くしたければ ink-muted / ink-faint の段を使う」を、そのまま実装した形。ホバーで見た目が変わらないようにするため、`variant="outline"` が内蔵する `hover:bg-muted hover:text-foreground` を `hover:bg-transparent! hover:text-ink-faint!`（Tailwind v4 の important 修飾）で上書きしている——同じプロパティを取り合う2つのユーティリティのどちらが勝つかはクラス名の並び順では決まらない（生成される CSS の登録順で決まり、ソースの記述順とは無関係）ため、並び順に頼らない上書きが要る。実際にビルドして生成 CSS を確認し、`!important` が付いていることを確かめた。

`ExportMenu` は `disabled: boolean` を `unusable: string | null` に変え、**プロファイルが2本以上で押せないときはドロップダウンを出さず、通常の `ToolbarButton` を出す**ようにした——開いても選べないメニューには存在理由が無いため。

理由の文言は `src/App.tsx` に集め、**ファイル未選択を先に見る**（「このツールは対応していません」より先に「ファイルを選んでください」を見せる——それが利用者にとって次に取れる、動ける一手だから）。活性の判断にモジュールの `type` を使わない既存の規約はそのまま守り、`tableExport` / `clipboardExchanges` の宣言の有無だけで決めている。

**このフォローアップでは `src/components/button-styles.ts` の `buttonBase` には触れていない。** 額縁の出力ボタン以外の小さなボタン（チップ・一覧の行・トーストの操作）は今も `disabled:opacity-50` のままで、押せない見た目が2種類並立している。理由を出す価値があるのは今回変えた5ボタンだけと判断し、残りは意図して手を付けなかった——`../open-issues.md` に記録済み。
