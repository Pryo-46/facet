# M3（用語集）申し送り: エディタの操作性

> **追記専用。** そのとき何が起きたかの記録であり、以後変えない。**いま開いている残件は [`../open-issues.md`](../open-issues.md) を見ること**——本書に書かれた残件は当時の状態を指す。計画立案の教訓は [`../lessons-for-planning.md`](../lessons-for-planning.md) に集約した。

M3 は実装・レビュー・E2E 完了。キーボード操作の共通化・IME 対応・境界規則・Undo/Redo・検索/フィルタが入り、M1・M2 の申し送りに挙げた M3 向けの申し送り（別名セル / kind の日本語ラベル / 非制御入力からの移行 / 行キーが配列 index / セル赤表示のキーが entityId のみ / 検索の照合規則）はすべて解消した。実機の日本語入力での確認も完了している。

### M4 で扱うもの

- **モーダルの配線点は用意済み**: `KeyContext.modalOpen` を true にすると操作言語が止まる（Esc の取り合いを構造的に排除する）。削除確認ダイアログを出すときは、額縁の `GLOBAL_KEY_CONTEXT`（`src/App.tsx`）とエディタの `onCellKeyDown`（`src/modules/glossary/GlossaryEditor.tsx`）の2箇所に渡す
- **用語が1件だけの状態でその行を消すとフォーカスが `document.body` に落ちる**: 削除後に移る先の行が無いため。M4 の空状態（新規作成ボタン・用語集の自動生成）と併せてフォーカスの行き先を決める。**行が残っている場合の削除は M3 で解決済み**（削除後の配列から鍵を引き、先頭行を消したときは新しい先頭行へ移る）
- **単一性違反の解消手段が無い**（M2 の申し送りからの積み残し）: M4 の削除機能が入って初めて閉じる

### M5 で扱うもの

- **外部変更の取り込みが無いことは E2E で実害として出た**: `git restore` でファイルを元に戻しても、アプリは開いたままの内容を表示し続ける。人間から見ると「戻したはずの内容が戻っていない」状態で、そのまま編集すると古い内容が書き戻る。**取り込み時に Undo 履歴を破棄する**（scope の実装順 M5 の既定）方針はこの経路でも正しい——履歴の中身は取り込み前のファイルを指しており、取り込み後にそこへ戻すとディスクの内容を無言で巻き戻すため
- **取り込みは `applyEdit` の4本目の経路になる**: 現在この関数（`src/App.tsx`）を通るのは編集・Undo・Redo の3経路で、いずれも「自動保存へ渡す」「整合性検証をやり直す」を必ず通る。外部変更もここに合流させること。履歴の作り直しは `selectFile` 内の `createHistory(result.data)` と同じ形になる
- **別名パネルを開いたまま外部変更が来ても表示は追随するはず**: `AliasCell` の下書き再同期は `aliases` の**内容**比較で行う（参照比較では Undo→Redo と区別できずデータ喪失を起こしたため。下記「実装で確定した事項」参照）。外部変更でも内容が変われば下書きを作り直す
- **`saveError` のクリア条件**（M2 の申し送りからの継続）: トースト通知の設計と併せて整理する

### M6 で扱うもの

- 出力ロジック（規約5）がモジュール規約6点セットの最後の空きスロット
- **種別の日本語ラベルは `src/modules/glossary/kind-labels.ts` にある**。Markdown 出力の見出しでも使い回すこと。`undecided` は既に「未分類」で、scope の実装順 M6 の「`### 未分類` として出力にも明示する」と表記を揃えてある。enum を拡張したらラベルの足し忘れをテストが検出する

### M7 で扱うもの

- 別名パネルの面・罫線・チップ、検索欄、種別フィルタチップの選択状態（`bg-ink text-canvas`）は既存の役割トークンの流用で仮置き
- **修飾キーの表示名は `altModifierLabel` / `primaryModifierLabel`（`src/core/keyboard/platform.ts`）を通す**。キーヒントを増やすときもベタ書きしない（macOS では Option / Cmd になる）

### いつでもよいが、忘れると実害化する残件

- **定義セル・種別セルは `mark(index, field)` を参照していない**（自セルの warning 条件だけを見る）。現状これらのフィールドを指す検証ルールが無いので実害は無いが、増えた時点で issue 一覧には出るのにセルが赤くならない
- **`@testing-library/user-event` を devDependencies に入れたが未使用**。キャレット・選択範囲の忠実度が要るテストを書くときに使うか、外すか
- **`resolveCommand` の細かい非対称**: macOS の `Ctrl+Backspace`（主修飾キーは Cmd なので素の Backspace として通る）と `Alt+Shift+↑↓`（`altKey` を先に見るため並び替えになる）。どちらも実害は小さいが、`Enter` / `Backspace` の分岐が余分な修飾キーを弾いているのと不揃い
- **`CellInput` の `caretAtStart` / `caretAtEnd` は完全に collapsed なキャレットのみ true**。選択範囲があると行間移動に1打鍵余分に要る（Excel 等と同じ挙動でもある）
- **編集1打鍵ごとに全ファイルの `checkConsistency` を再実行している**（M2 の申し送りからの継続）

### 実装で確定した事項（計画の前提に昇格）

- **キー解釈は `src/core/keyboard/keymap.ts` の `resolveCommand` ただ1箇所**。各コンポーネントは `KeyContext`（編集中か・空欄か・削除を認める欄か・キャレットが端か・欄自身が↑↓を使うか・並び替えが有効か・モーダル中か）を渡してコマンドを受け取り、自分の構造に写像するだけ。`e.key` を直接見るコードはコア以外に存在しない。**入れ子のリスト（別名パネル）が同じ関数で動くことを実証した**ので、2本目のツールもこの形に乗せる
- **行の同一性キーは `${id}#${出現順}`**（`src/core/row-keys.ts`）。データから毎回導出し、内部状態を持たない。**構造操作の後のフォーカス先は必ず「操作後の配列」から鍵を引くこと**——操作前の鍵は ID が重複していると別の行を指す（実装時に踏んだ）
- **新規行の名称は `新しい用語` を入れ、全選択状態でフォーカスする**。空文字はスキーマ違反（`minLength: 1`）で、自動保存が走った瞬間に次に開けないファイルを自分で作る。全選択は E2E の指摘（既定値を消す手間）への対応で、打ち始めればそのまま置き換わる
- **Redo は Ctrl+Shift+Z と Ctrl+Y（Windows/Linux）**。macOS は Cmd+Shift+Z のみ（Cmd+Y を Redo とする慣習が無いため）
- **テキスト編集中の Ctrl+Z もアプリの履歴が取る**。制御入力ではブラウザ標準の Undo が React の再レンダリングと食い違うため、挙動を一本化する。rev 10章の境界規則（編集中は操作言語を停止）への明示的な例外
- **編集・Undo・Redo は同じ後処理（`applyEdit`）を通す**。自動保存への反映と整合性検証のやり直しを取りこぼさないための単一経路
- **導出表示中（検索・フィルタ適用中）は並び替えだけでなく行追加も止める**。挿入するとその行が絞り込みに掛からず、見えないまま増えるため。理由は並び替えを止めるのと同じ「データ順と表示順の食い違い」
- **ローカル下書きと親の値の同期は参照でなく内容で比較する**（`AliasCell`）。`src/core/history.ts` の `redo` は Undo 前のオブジェクトを**同一参照**で返すため、参照比較だと「自分が上げた変更」と区別できず、パネルを開いたまま Undo→Redo すると表示だけ古いまま残り、次の打鍵で Redo した内容が消える（最終レビューで発見。回帰テストあり）
- **DOM テストは対象ファイル先頭の `// @vitest-environment jsdom` で切り替える**。グローバルの `test.environment` は `node` のまま（純ロジックのテストを重くしない）。Vitest の `globals` が無効なので `afterEach(cleanup)` を明示する。**要素は role とアクセシブル名で引き、レイアウトやクラス名に依存させない**（UI の微調整でテストを書き直さないため）。DOM テストは「壊れても画面は一見正常」な回帰——IME 誤爆・制御入力の巻き戻り・フォーカス移動・Undo の表示反映——に絞る

### rev への反映事項

- **10章**: グローバル層の Redo に **Ctrl+Y（Windows/Linux）** を追記する
- **10章**: 境界規則の明示的な例外として「**テキスト編集中も Undo/Redo はアプリが取る**（制御入力のため）」を追記する
- **10章**: 導出表示中に止めるのは並び替えだけでなく「**表示順とデータ順の対応が崩れる操作**（追加を含む）」と一般化する

### 実装計画そのものに含まれていた誤り（次回の計画立案への教訓）

計画（`docs/superpowers/plans/2026-08-02-m3-editor-operability.md`）に完全なコードを書いても、次の4件は実装・レビューの段で初めて出た。**計画のコードは検証済みの正ではなく、レビューを通す前提の下書きとして扱うこと。**

1. 履歴上限テストの期待値が実装の意味と1つずれていた（110件積んで末尾100件なら先頭は 10）
2. 行入れ替え後のフォーカス先を「移動前の配列」の鍵で指していた（ID 重複行が隣接すると別の行を指す）
3. window リスナーの依存配列が lint 警告を出した（挙動は正しいが、リポジトリの警告ゼロ基準を壊した）
4. **下書き再同期の参照比較（上記の Critical）**。単体では正しく見え、Undo と Redo を跨いで初めて壊れる。継ぎ目（額縁の履歴とエディタのローカル状態）にテストが無かったことが見逃しの原因で、実際の履歴を通す回帰テストを足して塞いだ
