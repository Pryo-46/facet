## Task 1 Step 7: `claude` の起動は PATH から直接通った

設計 決定9 は「`portable-pty` が Windows の `PATHEXT` 解決までやるかは実機で確認するまで分からない」とし、通らなければ `cmd.exe /c claude` への一段フォールバックを予定していた。**実機では不要だった。** `program: 'claude'` のまま `pty_spawn` を呼ぶだけで起動し、`CLAUDE_PROGRAM` / `CLAUDE_ARGS`（`src/core/terminal/pty-io.ts`）はブリーフのコードから変更していない。検証機の実行ファイルは `C:\Users\master\.local\bin\claude.exe`。

副次的な観察として、`claude` は起動直後にカーソル位置問い合わせ（`ESC[6n`）を送り、返事が来るまで描画を始めない。xterm は自分で応答するので画面上は問題にならないが、**端末を繋がずに PTY だけを検証すると「1行出て止まる」ように見える**。Task 1 の実装者が生の `console.log` で PTY 検証ボタンを組んだときに踏んだ観察で、次に PTY だけを単体で叩く人が同じ現象を「壊れている」と誤診しないための記録。

## Rust の例外が3つ目のカテゴリを得た（決定3）

自前 Tauri コマンドが `move_to_trash` の1本から、PTY コマンド4本（`pty_spawn` / `pty_write` / `pty_resize` / `pty_kill`。`src-tauri/src/pty.rs`）を加えて5本になった。**判断は一切置いていない**——実行ファイル名・引数・作業ディレクトリはすべて TypeScript 側（`src/fs/pty.ts` の `tauriPtyIo`）が決めて渡し、`pty.rs` に `claude` という文字列は現れない（Task 1 の自己レビューで grep 確認済み）。Rust の仕事はセッションを `Mutex<HashMap>` で持ち、バイト列を base64 経由で `Channel` に流すことに尽きる。

## 実機確認の1回目で出た6点——うち3点は同じ1つのバグだった

**根本原因（1バグ・3症状）**: `src/components/TerminalTab.tsx` の起動 effect で、`spawn` に渡す `onExit` が `disposed` フラグで守られていなかった。`main.tsx` は `<StrictMode>` を使うため、開発時は次が起きる。

1. 1回目のマウントで PTY-A を起動 → StrictMode が即アンマウント（`disposed` が true になる）
2. 2回目のマウントで PTY-B を起動（**これが実際に使われる端末**）
3. PTY-A の `spawn` が解決 → 捨てる側なので `ptyIo.kill(A)` を呼ぶ
4. **kill された A の終了イベントが Rust から返る → 守られていない `onExit` が発火 → 台帳の `markExited` がセッションを `exited` にし `ptyId` を `null` に落とす**

生きている B は動き続けるので画面は正常に見えるが、**台帳の上では「終了済み」**になる。観測された症状は3つ:

- 起動直後に「終了しました（コード 1）」が必ず出る
- `hasRunning` が false を返す → **フォルダ切替の確認ダイアログが出ない**
- `ptyId` が `null` に落ちている → **タブを閉じても `kill` が飛ばず Claude が残り続ける**

**Task 4（`TerminalTab` の初版）のテストはこの穴を取り逃がした。** 理由は、テストが「捨てた側が `kill` される」（上記の手順3）までは固定していたが、「捨てた側が `onExited` を呼ばない」（手順4以降）を主張していなかったこと。StrictMode の二重マウントを再現するテストはあっても、**捨てられた側の `onExit` コールバックを実際に発火させて、それが台帳へ伝播しないことまでは見ていなかった**——「kill が呼ばれた」ことと「呼ばれてはいけないコールバックが呼ばれていない」ことは別の主張であり、片方を固定してももう片方の穴は残る。**次に似た形の「捨てる側／生き残る側」の分岐を書くときは、捨てた側に対して禁止したい経路（コールバック発火・状態書き込み等）を明示的に発火させて何も起きないことまで確かめること。**

Task 10（`fa8630d` 系のコミット）で修正し、`cb.current.*` を呼ぶ**6経路すべて**（`TerminalTab.tsx` 内の `onExit` / `onData` の各分岐）を `disposed` で守る形にした。StrictMode で包んだ状態で「捨てられた側の `onExit` を発火させても `onExited` が呼ばれないこと」「生き残った側の `onExit` を発火させたら呼ばれること」の両方をテストで固定している。

**残り3点は独立した指摘。**

- **ペインを広げても端末の桁数が追従しない**（Task 10）: `fit()` が `hidden` の変化でしか走っていなかった。`ResizeObserver` で端末を包む要素の寸法変化を監視し、**桁数・行数が実際に変わったときだけ** `pty_resize` を呼ぶ形にした。ドラッグ中に毎フレーム `pty_resize` を撃つと子プロセスに SIGWINCH が飛び続けるため、この間引きは体感の問題ではなく実装上の必須要件。
- **ウィンドウを縮めるとアプリ全体がスクロールする**（Task 11）: `<main>` に `overflow-hidden` が無く、ペイン `<aside>` が `shrink-0` ＋固定 px 幅だった。`overflow-hidden` を足すだけでは足りず（はみ出しが見えなくなるだけでエディタが画面外へ押し出される）、`ResizeObserver` でウィンドウ幅の変化を監視してペイン幅を `resizeColumns`（`src/core/column-resize.ts`）に通し詰め直す形にした。
- **Shift+Enter で1回しか改行できず、2回目以降は送信になる**（Task 10 で実装、Task 10 の追加修正で確定）: 原因は xterm の `attachCustomKeyEventHandler` が、戻り値 `false` で「xterm は処理しない」と伝えたつもりでも、**`preventDefault()` を自分では呼ばずに抜ける**実装だったこと。ブラウザの既定動作（隠しテキストエリアへの改行挿入）が生き残り、次の入力でその改行が PTY へ送出されていた。facet 側のハンドラで明示的に `preventDefault()` を呼んで解決した。Claude Code の `/terminal-setup` は iTerm2 / VSCode の設定ファイルを書き換えるものであり、埋め込み端末には効かないため、この機能は facet 側で独自に実装した（設計スペックには無かった追加）。

## 実装で計画から変わったこと

- **タブバーの ARIA ロールは使わない。** 設計計画は `role="tablist"` / `role="tab"` を使う想定だったが、**人間の裁定**（スクリーンリーダー利用者は考慮しない）により削除し、選択状態は `aria-pressed` で表す（Task 3〜4 相当のレビューで確定）。
- **タブを閉じるときに確認ダイアログを出す。** 設計スペックの決定12 は「確認は出さない」と決めていたが、**実機で使った人間が覆した**（Task 11）。実機で「タブを閉じても Claude が残る」と見えたのは上記のバグによるもので、修正後は確認なしで即座に殺される動きになるため、そのぶん確認が必要という判断。既存の `pushModal` / `ConfirmDialog` にそのまま乗せており、実行中でないタブ（`exited` / `failed`）は確認なしで閉じる。
- **`AppController.openFolder` の戻り値を `Promise<void>` から `Promise<boolean>` に変えた**（Task 11 のレビュー指摘対応）。フォルダ切替が失敗した経路で端末セッションだけを失わないための変更で、`false` を返す分岐は4つ（`closeCurrentFile` の flush 失敗／トークンすり替わり2箇所／`scan.unreadable`／catch）。
- **`src/core/column-resize.ts` に省略可能な `referenceWidths` を足した。** 額縁のペイン幅が「意図した幅」と「実際に表示している幅」を分けて持つ必要が出たため（ウィンドウ縮小時の追従）。**省略時の挙動は不変**——用語集・エラーカタログは渡していない。
- **額縁レベルの DOM テスト（`src/App.dom.test.tsx`）を新設した。** このリポジトリで1本目。端末にフォーカスがある間 `Ctrl+Z` が Undo を起こさないことを主張しており、`open-issues.md` の長年の穴（後述）を塞いだ。
- **同梱 Skill は `SKILL.md` と `scripts/` だけを配る。** `evals/`・`package.json`・`.gitignore` は除外する（各 Skill 9ファイル→3ファイル。コミット `0c8eab3`）。除外リスト方式なので、Skill が自分の動作のために新たに足すファイル（`references/` 等）は既定で同梱される。

## テストを1件削除した

`src/components/TerminalPane.dom.test.tsx` の「タブが多くてもタブバーからボタンが消えない」（タブ5本でも `＋` と最初のタブが DOM に残ることを主張していたテスト）を削除した。**jsdom にはレイアウトが無く `overflow` の実効を測れないため**、`overflow-x-auto` / `shrink-0` の有無に関わらず必ず通ってしまい、回帰検出力がゼロで「はみ出しは守られている」という誤った安心を与えるテストだった。同じ観点は実機確認の項目（タブ5本でも `＋` が押せること）へ移し、人間が2回目の実機確認で確認済み。
