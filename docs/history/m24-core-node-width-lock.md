## 何を作ったか

- **幅を内容から導出するのをやめた。** 課題ツリー・ロジックツリーとも、全ノードが **320px 固定**になった。表現は `wrapWithin` の **`minWidth === maxWidth`**——新しい書き方ではなく、シーケンスの答えセル（`ANSWER_WRAP`）が既に使っていた同じ手である。これで右上のバッジは列ごとに縦一列に揃う（rev.3 が言う「スキャン性」の主張そのもの）。
- **高さは内容のまま。** 一度は「閉じた箱に出る文章（課題のタイトル・見送りの理由・ロジックのノード）を3行で打ち切る」を実装したが、**実機で撤回した**（下の節）。**ノードの高さは M24 の前と同じく内容が決める。**
- **`wrapWithin` の `maxLines` も、`CellInput` の `scrollTop` リセットも残っていない。** どちらも打ち切りのために足したもので、打ち切りが無ければ前者は使用0件の死んだ API、後者は決して発火しない no-op になる（内部スクロールは打ち切りがあって初めて起きる）。**使用0件のものを残さない**のはこのリポジトリの既定の判断で、`text-lg` を実使用0件のまま閉鎖した M23 と同じ扱い。
- **消えた定数3つ**——`ISSUE_MAX_WIDTH`(320)・`ISSUE_TITLE_MIN_WIDTH`(128)・`NODE_MIN_WIDTH`(96)。**改名1つ**——`NODE_MAX_WIDTH` → **`NODE_WIDTH`**（上限ではなく固定値になり、名前が嘘になったため）。**3つの 320（`BOX_WIDTH` / `NODE_WIDTH` / `LABEL_MAX_WIDTH`）は共有定数に束ねていない**——2つは固定値・1つは上限で、意味の違うものが同じ名前になる方が危険である。
- **`layout.ts` から幅の分岐そのものが消えた。** `if (rows.length > 0 || deferred)` の if/else と、それに付いていた 25 行の JSDoc（「箱の下限から枠のぶんを引くと、空けた枠が文章を食って入力欄が数 px になる」という実機の欠陥の説明）が、**構造ごと消えた**——固定幅では枠は常に固定幅の中から取られるので、枠が文章を食って下限を割る経路が成立しない。同じ理由で **`wrapWithin` の `minWidth <= maxWidth` 依存**（食い違うと `maxWidth` を採るので、逆転するとタイトルが黙って下限を割る）も課題ツリーからは消えた。**`wrap.ts` 側の注意書きは残してある**——シーケンスがまだこの依存の上にいる。
- **文書。** [`../overview-rev.md`](../overview-rev.md) 9章の「測定層と描画層が同一のフォントトークンを参照しなければならない」の項に、**フォントに追従するのは高さ（行数）だけになった**という帰結を足した（シーケンスだけ扱いが違うことを含む）。UI ノート D3 に **M24 での実施結果**の追記小節を置き、§8 の表の直後に**実施状況**の1行を足した（表そのものには列を足していない——この表は順位を示すもので、完了を記す様式を持たない）。[`../open-issues.md`](../open-issues.md) は**消1・書き換え1・足す1**。

## 実装で確定した事項

### `LogicTreeEditor.font.dom.test.tsx` の番人が巻き添えで死ぬところだった——観測点を幅から高さへ移した

このテストは「Web フォントの読み込み完了（`document.fonts.ready`）でノードが測り直されるか」を、**ノード矩形の `style.width`（142px → 262px）**で観測していた。測定器を「呼ばれるたびに太く測る」偽物に差し替え、幅が動くことで測り直しを証明する形である。**幅が定数 320 になると、測定器を差し替えても幅は動かない**——番人が黙って何も検証しなくなる。

**観測点を `style.height` へ移した**（決定4）。高さは行数を通じてフォントに依存し続けるので、太さが倍になれば折り返しが増えて高さが動く。**期待値はピクセルのリテラルで書いていない**——実測した1行ぶんの高さから `inset + oneLine * 2` の形で導いている。段や `leading` が変わっても黙って取り残されないためである。

**文言長を12文字から20文字へ変えた。** 内容幅 298px（320 − `NODE_INSET_X` 11×2）に対し `L × perChar ≦ 298` が `perChar` 10 で真・20 で偽になる L の範囲は **15 以上 29 以下**で、その中央付近の 20 を採った。**12文字のままでは 12×20＝240 ≦ 298 で2回目も1行に収まり、高さが動かない**——赤くならず、番人が黙って死ぬ。この導出はテスト本文のコメントに残してある。

**番人が本当に番をしていることを、破壊テストで実証した**（Task 2 Step 3）。`measurerKey` から `fontGeneration` を一時的に外すと高さが 38px のまま（期待 62px）で FAIL し、戻すと PASS した。**「不等式なので自動追従する」という思い込みが M23 決定1 で実際に外れている**ので、今回は緑を見るだけで済ませていない。

**この作り替えを、幅の固定より前に置いた**（Task 2 が Task 4・5 より前）。**現行コード（可変幅）でも緑になる形で書き換えたので、「幅の固定を入れたついでに 320 へ書き換えて緑にした」という退化が構造的に起きない。** 実際、幅を固定した後もこのテストは緑のままだった。

### `ISSUE_TITLE_MIN_WIDTH` が守っていた不変条件は、定数からテストへ移った

`ISSUE_TITLE_MIN_WIDTH`（128）は「箱の下限ではなく文章の下限」という概念を持つ定数で、固定幅では出番が無くなる。**ただし「一番広い枠を引いてもタイトルが痩せすぎない」こと自体は要る**——`BOX_WIDTH` を縮めるか、バッジの語を伸ばした将来の変更に対する門番である。

これを `layout.test.ts` のアサーションへ移した（「一番広い枠（仮説なしバッジ）を引いても、タイトルは日本語8字ぶんを残す」）。一番広い枠は「仮説なし」バッジ（`text-sm` 14px で4字 ≒ 56 ＋ `BADGE_PADDING_X` 6×2 ＋ `BADGE_BORDER` 1×2 ＝ 70）である。**下限をリテラルで書いていない**——`fonts.title.measure('あ'.repeat(8))` とテストの測定器から導いている。段が変われば「8字ぶん」の px は動くので、リテラルで書くと M23 決定1 と同じ隠れリテラルになる。

## 実機確認の所見——3行の打ち切りを撤回した（2026-08-25）

**M24 で最も残す価値のある記録はこれである。**

- **人間の言葉**: 「ロジックツリー、課題ツリーですが、４行以上になってもキャレット出現してないです。」
- **症状**: 上限行数（3行）で打ち切られた `textarea` に4行目以降を打つと、**キャレットが見えない＝溢れた行へ到達できない。** 設計スペックが決定3 で「未検証の前提」と名指しし、チェックリストの項目7 に送っていた「`overflow: hidden` の `textarea` でブラウザがキャレットに追従して内部スクロールする」が、**実機で偽だった。**
- **なぜ致命的か**: この前提の上に「省略記号を出さず打ち切るだけ」という決定3 が丸ごと乗っていた。前提が偽なら、**打ち切った箱は4行目以降を編集できない箱**になる。読めないだけなら劣化で済むが、編集できないのは機能の欠落である。
- **対処**: **高さの打ち切りを撤回した。** 幅の固定だけを残し、高さは内容が決める M24 前の挙動に戻した。撤回に伴って `WrapOptions.maxLines`・`NODE_MAX_LINES`・`BOX_TEXT_MAX_LINES`・`CellInput` の `scrollTop` リセットと、それらのテスト9本が消えている。
- **検討して採らなかった代案**（人間が選択肢から選んだ）:
  - **フォーカス中だけ `overflow-y: auto` を許し、スクロールバーを `scrollbar-width: none` で消す。** `auto` なら確実にキャレットへ追従し、バーを消せば幅を1pxも食わないので測定の前提が崩れない。**設計時に `overflow-y: auto` を退けた理由（スクロールバーが幅を食う）には、この逃げ道があった**——当時それを検討していなかったのは設計の穴である。
  - **フォーカス中は箱を伸ばす。** 課題ツリーの展開パネルという先例はあるが、クリックのたびに木が組み直されて周囲のノードが動き、1パス描画の前提と正面から衝突する。
- **`ISSUE_TITLE_MIN_WIDTH` が守っていた不変条件のテストは残っている**——撤回したのは高さだけで、幅の固定は生きているため。

**一般化した教訓は [`../lessons-for-planning.md`](../lessons-for-planning.md) に足した。** 要点は「**描画側の挙動に関する前提は、設計判断の土台にする前に最小の実験で潰す**」——実装を1マイルストーン分積んでから実機で潰れると、積んだものを剥がす作業が要る。今回は剥がせる形（コミットが機能ごとに分かれていた）だったので安く済んだ。

## 次へ

**UI ノートの残りは D の前半（判断として閉じた）・E・F。**

- **D（レイアウト固定）** ——**幅の固定は閉じた。高さ（省略）は開いたままである。**
  - **テーブルの行高固定＋2行省略は「変えない」と決着した**ので、蒸し返すなら (1) `CellInput` の `MAX_ROWS = 8` に付いた「行の高さが揃わなくなるが、読めないよりよい」（M10 決定17）を反転させる理由と、(2)「省略した全文をどこで読むか」の答え——テーブルには展開パネルに相当する場所が無い——の2点に答えを持ってくること。
  - **ツリーの高さの打ち切りは、実機で撤回した。** 再挑戦するなら**先に「4行目以降をどう編集させるか」を決めること**——`overflow: hidden` の `textarea` はキャレットに追従しない、というのが実機で得た事実である。有力な逃げ道は**フォーカス中だけ `overflow-y: auto` にし、スクロールバーを `scrollbar-width: none` で消す**（`auto` は確実に追従し、バーを消せば幅を食わないので測定の前提が崩れない）。**この案は M24 の設計時に検討されていなかった**——`overflow-y: auto` を「スクロールバーが幅を食う」1点で退けたのが設計の穴だった。
- **E（フォント同梱。U1 未決）** ——ウェイト階層（D8）の全面展開は引き続き E 待ち。M24 は触っていない。
- **F（見送り集計ほか。D17・D18、§1.1 の select 置換・角丸統一）** ——手つかず。**U4（破線エッジの意味）は実装が既に答えを持っている**ので、問いとしては閉じている（[`../open-issues.md`](../open-issues.md) の F の項を参照）。
- **ダークの吟味**は M21 から持ち越したままで、M24 も触っていない。
