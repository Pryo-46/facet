## ヘッダー見切れの原因と、伸縮を1要素に閉じた形

旧ヘッダーは `<header className="flex items-center gap-4 ...">` の子要素すべてが `flex` の既定 `min-width: auto` を持っていた。フォルダのパス（`{projectDir && <span>...}`）はこの並びの中に素の `<span>` として置かれていたため、パスが長くなっても縮まず、右端の畳みボタン・ペイン開閉ボタン・テーマ切替を画面外へ押し出しうる状態だった。

修正（`d731ba3`）は、**帯の中で伸縮を引き受ける要素を1つに絞る**という形。左側の操作群（フォルダを開く／Undo・Redo／ExportMenu）と右側の操作群（畳みボタン・ペイン開閉・テーマ切替）をそれぞれ `<div className="flex shrink-0 items-center gap-2">` でまとめて `shrink-0` を明示し、中央のパス表示だけに `min-w-0 flex-1 truncate` を与えた。この規約は `docs/overview-rev.md` 9章へ反映済み。

**このパス表示自体は次のコミット（`001d8dc`）で額縁から消え、サイドメニュー側（`FileList.tsx`）へ移った**（Task 4／`56ea814`）。ヘッダーには `projectDir` を表示する要素がもう無いため、上の `min-w-0 flex-1 truncate` の対象は実質「無くなった」形になる——伸縮規約そのものは活きているが、現在ヘッダーで伸縮を引き受ける要素は無い（右側の操作群を画面外に追いやる長い要素が無い状態）。

## 空状態を `createEmpty` へ移した判断と、既存0件ファイルの救済の形

シーケンス（`a87941e`）・ロジックツリー（`54b5de3`）の両方で、キャンバス中央に出していた「クリックして開始」ボタンを廃止し、**`createEmpty` が最初の1件（シーケンス＝参加者1人、ロジックツリー＝ルート1件）を持った状態でファイルを作る**形に変えた。新規作成の入口を「空のキャンバスを押す」という1回きりの特殊操作から外し、以後はどちらのツールも「打ち始めればよい」状態でファイルが開く。

問題は**外部編集で作られた0件ファイル**（`createEmpty` を経由しない、手で書いたりSkillが作ったりした JSON）で、これは今後も起こりうる。2本のキャンバスは救済の形が異なる：

- **シーケンス**: 「参加者を追加」「ステップを追加」のボタンを帯に常設した（sequence M3 で先に実装済み）ので、0人の状態でも常設ボタンから復帰できる。追加のケアは不要だった。
- **ロジックツリー**: 帯のボタンは**0件のときだけ**出す（`data.nodes.length === 0 && (...)`）。常設にしなかったのは、「フォーカス中のノードを持つ」という新しい状態を作らずに済ませるための意図的な判断——常設のボタンで子/兄弟を追加するには「どのノードに対して追加するか」を決める前提が要り、M13 のスコープでは踏み込まなかった。この帰結として、**ノードが1件以上あるロジックツリーには、マウスだけでノードを増やす一般的な動線が無い**（追加は `Enter`/`Tab` のキーのみ）。これは `open-issues.md` に新規追加した（下記）。

## 問いラベルの高さが行高に入っていなかった欠陥と、`text-xs` の見本要素を別に立てた理由

シーケンスの行高計算（`layout.ts` の `stepHeight` 系）は、ガター列に出す問いラベル（例:「実行済みだったら？」）の高さを一切見ていなかった。ラベル文字列が長い行では、ラベルが行の下端からはみ出して次の行に食い込む欠陥があった。

修正は2段階。

1. `72d7298`: 行高の算出に問いラベルの高さを算入し、質問文言そのものを短くした（例: 「届かなかったかもしれない。それでよいか？」→「届かなくてよいか？」。この文言変更は `docs/sequence/sequence-design-notes.md:80` の導出テーブルにも同じ文言で載っており、本コミットで直し忘れていたのを Task 11（本ドキュメント作成時）で発見し修正した）。
2. `b242099`: 1段階目のレビューで、`GutterSlot` が実際に描画する文字列（`ifExecuted` は `└ ` を前置して描く）と、行高測定が測る文字列（素の問い文言。前置詞なし）がずれていることが発覚した——72d7298 が閉じたのと**同種の乖離**が別の場所に残っていた。`gutterLabelText` という1つの関数に文字列組み立てを集約し、描画・測定の両方がそこを通す形にして解消した。また、ラベル列は `text-xs`（12px）なのに、既存の測定器の既定値（フォールバックフォント）は `text-sm` 用の `FALLBACK_SEQ_FONT` を使い回していたため、jsdom 環境では2つの測定器が同じ値を返し続けてテストが両者の違いを検出できない状態だった。ラベル用に `FALLBACK_LABEL_FONT`（12px・行間1.5）を別途立てて解消した。

## 実機確認について

M13 の実装過程では、各タスクの Step「`npm run tauri dev` による実機確認」を**統括者裁定によりすべてスキップした**（`progress.md` Ruling R4）。理由は、ユーザーが「UI の見た目は実機で確認する」と明示していたため。したがって、以下は**まだユーザーによる実機確認を経ていない**——本ドキュメントの作成時点（Task 11）でも `npm run tauri dev` は実行していない：

- ヘッダーを狭めても右端の3操作（畳み・ペイン開閉・テーマ切替）が画面外に出ないこと
- サイドバーの新規作成ボタン4つの右端揃い、パス表示、削除アイコンのホバー赤
- `KeyHints` 帯の `bg-surface/80`（コードベースに前例のない不透明度指定。下記「残った小さな指摘」参照）の可読性
- シーケンス・ロジックツリーの新規ファイルが最初から1件を持った状態で開くこと、帯のヒントが右上に出て指摘バナーと重ならないこと
- シーケンスの行高修正後、長い問いラベルが実際のフォントで折り返さず収まること

### 実機確認で出た指摘（M13 の中で直したもの）

ユーザーが実機で確認し、次の指摘が出た。いずれも同じブランチで直している。

- **アイコンの選び直し**: エラーカタログを `TriangleAlert` → `BookAlert`（カタログ＝冊子という語感に寄せた）
- **見出しの位置と大きさ**: 「facet」がサイドメニューと同じ幅（`w-64`）を占め、操作の始まりがエディタの左端に揃うようにした。あわせて `text-lg` → `text-2xl`。**これはフォントの段（M7 決定6）の改訂を伴った**（上の rev 反映の項を参照）
- **問いラベル列の幅**: `QUESTION_LABEL_WIDTH` を 104 → 164 に広げ、立つ問いがすべて1行に収まるようにした。`questions.test.ts` の検査も「2行まで」から「1行」に強めてある。**ただしこの検算は jsdom 用の概算器を使っており、実フォントの字幅は測れない**——実機で折り返したら、まずここを疑うこと
- **文言がガターの問いラベルに重なる**（`layout.ts`）: 参加者が少なく文言が長い図（`self` の内部処理など）で踏んだ。原因は `gutterX` が**参加者ヘッダの右端しか見ておらず、ステップ文言の幅を勘定していなかった**こと。根はもう一段深く、**文言の置き方（self は起点の真上／呼出は from-to の中点／参照切れは図の左端）がレイアウトではなくエディタ側にあった**ため、レイアウトは文言がどこまで伸びるかを知りようが無かった。置き方を `layout.ts` へ移し（`SeqRow.labelLeft`、入力に `isSelf` を追加）、`gutterX` はその右端も見るようにした。**描画側で `labelLeft` を計算し直さないこと**——2箇所に分かれた瞬間に同じ重なりが戻る
