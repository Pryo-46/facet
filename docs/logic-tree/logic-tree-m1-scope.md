## この段階の目的

**会議に持ち込んで、キーボードだけでロジックツリーを打ち切れる状態にする。**

facet の第一関門は「会議のスピードに入力が追いつくか」（rev 11章）であり、それは入力・表示・保存の3つが揃えば検証できる。マウス操作も出力も、この検証には不要である。

**動くものを1回会議に持ち込むことが、残りの設計判断の精度を上げる最短経路である。** 第2段階以降の機能は、実際の使用で必要性が確認されてから着手する（rev の「実際の使用が実際のギャップを明らかにする」）。

## 含むもの（IN SCOPE）

### 1. データとファイル

- `logicTree` の JSON Schema（スキーマが正、TypeScript 型は自動生成）
  - ID規約: `node_` プレフィクス ＋ 英数字62文字アルファベット・10文字 nanoid（rev 5章）
  - ノードのフィールド: `id` / `text` / `children`（当初の想定）
    - **（logic-tree M1 の実装で確定）**: `children` の入れ子はやめ、**平坦な `nodes` 配列 ＋ 親を指す `parentId`** にした（`schemas/logic-tree.schema.json`）。理由は3つ——(1) 兄弟順の正本を配列順に一本化できる（rev 5章）、(2) コアの行操作（`src/core/list-ops.ts`）がフラットな配列を前提にしており、そのまま使える、(3) **入れ子では循環・多重ルート・親の参照切れが構造上書けず、壊れたファイルがレベル1拒否に倒れる**（rev 5章「拒否は解釈不能な場合に限る」に反する）。代償の「JSON を上から読んでも木の形が分からない」は、編集のたび配列を DFS 行きがけ順へ正規化することで埋めた。詳細は [`../history/logic-tree-m1-keyboard-editor.md`](../history/logic-tree-m1-keyboard-editor.md)
  - 単一ルートの木（親を持たないノードは存在しない）
  - `schemaVersion` は `const: 1`
- エンベロープ（`type` / `schemaVersion` / `title` ほか、既存モジュールと同形式）
- ファイル読み込み・オートセーブ（デバウンス）
- **二段検証**（レベル1: スキーマ検証 → 拒否 ／ レベル2: 整合性検証 → 受け入れて赤表示）
  - 整合性検証の内容: ID重複、親子関係の循環、ルートの単一性
    - **（logic-tree M1 の実装で確定）**: これに**親の参照切れ（`missing-parent`）を足して4種**とした（`src/modules/logic-tree/consistency.ts`）。循環と参照切れは原因も直し方も違うのに、どちらも「根から到達できない」で同じメッセージになると、画面を見た人が何を直せばよいか分からないため。平坦＋`parentId` にした帰結として、この2つがデータ上区別できる
- マイグレータの枠（初版につき恒等）

### 2. キーボード操作（rev 10章の階層・リスト系ファミリー標準）

- `Enter` = 兄弟を直後に追加
- `Tab` = 子を追加
- 空欄で `Backspace` = 削除
- `Alt+↑↓` = 兄弟の並び替え
- 矢印 = ノード間フォーカス移動
- `Esc` = 編集中はキャンセル、非編集は選択解除
- `Ctrl+Z` / `Ctrl+Shift+Z` = Undo / Redo（メモリ内・ファイル単位）
- **IME 対応**: composition イベントで変換中を判定し、変換確定の Enter がノード追加に誤爆しないこと
- **境界規則**: インライン編集中はキーイベントを編集対象が取り、操作言語は停止。例外は編集境界キー（Enter / Tab / Esc / 空欄Backspace）のみ
- 実装は**共通フック／モジュールに一元化**する（ツールごとの自前ハンドラ禁止。rev 10章 実装規約）

> `Alt+↑↓` を M1 に含める理由: 配列順が兄弟順の正本であり、順序を直す手段が1つも無いと会議で詰まる。実装は splice 1回で済むため安い。

### 3. 表示

- **測定層**: `(文字列, フォントトークン) → {幅, 高さ, 行配列}`
  - オフスクリーン `<canvas>` の `measureText` を使い、**同期的**に測る（DOM に触れない・リフローを起こさない）
  - 最大幅 **320px** で折り返し、最小幅あり
  - **折り返し位置をここで確定させ、描画層には行配列を渡す**（ブラウザの折り返し判断に依存しない）
  - 測定と描画は**同一のフォントトークン**（rev 9章）を参照する
  - DOM 非依存 = ユニットテスト対象
- **レイアウト層**: `(ツリーデータ, サイズマップ) → Map<ノードID, {x, y}>`
  - Reingold–Tilford 系（可変ノードサイズ対応）を自前実装
  - **完全な純粋関数**。入力が同じなら出力が同じ（「図は導出」のコードレベルでの担保）
  - スナップショットテスト対象
- **描画層**: 3レイヤ構成
  - 背景レイヤ（M1では空。シーケンスの失敗ゾーン用に枠だけ確保）
  - エッジレイヤ（SVG）
  - ノードレイヤ（絶対配置 DOM）
  - 3レイヤに同一の transform を当てる
- **ビューポート**: d3-zoom
  - `Ctrl+ホイール` = カーソル中心ズーム
  - `Space+ドラッグ` / 中ボタン = パン
- 空状態からの開始（キャンバス中央の「クリックして開始」でルートを作る）

### 4. 完了条件（動作で判定する）

1. 空の状態から、**会議1回分のツリー（30〜50ノード）をキーボードだけで打ち切れる**
2. **日本語入力で、変換確定の Enter がノード追加に誤爆しない** ← 最重要
3. アプリを閉じて開き直すと、同じツリーが同じ形で出る
4. `Ctrl+Z` が期待どおり戻る（1操作1コミット）
5. ノードが増えても、ズーム・パンで全体と細部を行き来できる
6. 測定層・レイアウト層のユニットテストが通る

**2 が通らなければ M1 は未完とする。** ここが崩れると会議で使えず、他がどれだけ出来ていても意味がない。

## 含まないもの（OUT OF SCOPE）

以下は plan に含めないこと。実装しない。

### マウス操作の一切

- ドラッグでの親付け替え・兄弟並び替え（3分割ドロップ判定、挿入インジケータ、循環防止）
- ホバーで現れる「+」ハンドル
- 右クリックのコンテキストメニュー
- 矩形選択・複数選択・Shift+クリック
- ノードの複製

> マウス操作は今日のセッションで設計済み（`logic-tree-canvas-tech-notes.md` 論点6）だが、**会議中に実際に使うのはキーボードのはず**であり、優先度は使ってみるまで確定しない。先に作ると使われない機能に時間を使うことになる。

### 表示の作り込み

- レイアウト変更時のアニメーション（M1 では瞬間移動でよい）
- 折りたたみ／展開
- 葉数バッジ
- 未定義ノードの可視化・赤表示
- ダークモード、デザイントークンの作り込み（仮置きのまま進む）

### 出力・連携

- Markdown 出力、Mermaid 出力、クリップボードコピー、.md 書き出し
- 外部変更検知（フォルダ監視、トースト、二択ダイアログ、退避と復元）
- 検索・フィルタ
- 用語集への参照（クロスファイル参照機構は未実装であり、ここでは扱わない）

### 禁止事項

- **`core/canvas` 等への共通化・抽象化を行わないこと。** シーケンスエディタと共有できそうな部分があっても、この段階では素直にロジックツリーの中に書く。一般化はシーケンス着手時に「2つ目の実例が出たことで見える一般化」として行う（rev4 が用語集とエラーカタログで採った手順）
- **`Ctrl+C` / `Ctrl+V` に他の意味を割り当てないこと。** 複製は後回しであり、押しても何も起きない状態にしておけば後から本来の意味で入れられる
- **座標・幅・表示状態をデータ（JSON）に入れないこと。** 位置はレイアウト関数が毎回導出する。幅は測定層が文言から算出する
- **キャンバスライブラリ（React Flow / tldraw / elkjs / dagre）を導入しないこと。** 検討済みで不採用（理由は tech-notes 論点2）

### 削ったものの回収コストが低い根拠

- マウス操作は「挿入位置＝(親ID, インデックス) の書き換え」というコマンドを呼ぶだけであり、そのコマンドは Enter / Tab の実装時に既に存在する
- アニメーションはレイアウト層が純粋関数なので、前回と今回の座標 Map を補間する層を後から挟むだけ
- 出力はモジュール規約（rev 6章）の提供物として枠が決まっている
- **いずれもスキーマ変更を伴わない**
