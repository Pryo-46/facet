## 1. 背景と目的

**会議中に Skill を走らせる動線が、いまアプリの中に無い。**

`rev 4章` は Skill 群（用語登録・エラー登録・下書き生成・レビュー）を「アプリと並ぶ正式な成果物」と位置づけているが、それを呼ぶには別ウィンドウで Claude Code を開き、プロジェクトフォルダへ移動する必要がある。会議は秒単位で流れる（`rev 2章`「入力速度最優先」）ので、この往復は実際には行われず、**Skill は作ってあるのに使われない**状態になっている。

本マイルストーンは、ヘッダのボタン1個で**右ペインに Claude Code の端末を開ける**ようにする。VSCode のターミナル版 Claude Code と同じ体験を facet の中に持ち込む。

### 含まないもの

- **Claude Code 以外の端末。** タブで開けるのは `claude` のセッションだけ。汎用ターミナルへは広げない
- **タブ名のリネーム。** 連番（`Claude 1` / `Claude 2`）固定
- **ペイン幅・畳み状態の永続化。** M8 決定7（列幅は「アプリを閉じるまで」）と同じ扱い。アプリ内に `localStorage` の利用は現在1箇所も無く、この一貫性を崩さない
- **ペインの開閉／フォーカス脱出のショートカット。** 決定11 で意図的に落とした（帰結は同項に記す）
- **Skill 本体の追加・改修。** エラー登録 Skill は既にあり、`open-issues.md` の「エラー登録 Skill が無い」は M10 完了時点の記述が古い（本書の範囲外だが、完了時に突き合わせること）

## 2. rev への位置づけ

本書は `overview-rev.md` を3箇所改訂する。**実装の完了コミットで rev へ反映し、申し送りに TODO として残さない**（M4 の教訓）。

### 決定1: 4章の原則は維持し、「端末のホスト」を例外として明記する

`rev 4章` は「AI（Claude）はアプリに組み込まない。**APIの呼び出し・アプリ内AI機能は作らない**」「アプリとの接点はファイルだけ」と定めている。

**この機能は 4章 が禁じているものではない。** facet は Claude の出力を一切解釈せず（バイト列を xterm へ渡すだけ）、API も呼ばない。データの接点は依然としてファイルだけで、増えるのは**起動の動線と置き場所**だけである。

したがって 4章 には次の趣旨を書き足す——**アプリ内 AI 機能は作らないが、AI を起動する場所は提供する。facet は端末のホストであって、AI の対話相手ではない。**

この線引きは実装の判断基準として使える。**「Claude の出力を読んで何かを決める」実装が現れたら、それは 4章 違反である。** タブ名を会話の内容から自動で付けない（決定8）のはこの基準の直接の帰結。

### 決定2: 4章の運用推奨「AIに作業させる間は対象ファイルをアプリで閉じる」を撤回する

`rev 4章` の現行の運用推奨は、本機能の目的と正面から矛盾する。**隣に並べて使うために作るものだからである。**

撤回してよい根拠は、受け皿が既に完成していること。M5 の外部変更検知が、未保存編集が無ければ再読み込み＋トースト（**Undo 履歴は破棄**）、あれば二択ダイアログという形で衝突を処理する。**「AI が隣に居る」を前提にできる状態は既に出来上がっており**、本機能のために新しい仕掛けは要らない。

### 決定3: 7章の「Rust は原則書かない」の例外に3つ目を足す

自前 Tauri コマンドが `move_to_trash` の1本から5本になる（決定7）。

例外として認める根拠は `move_to_trash` と同じ——**判断を一切置かないこと**。実行ファイル名・引数・作業ディレクトリはすべて TypeScript 側が決めて渡し、Rust 側のコードに `claude` という文字列は現れない。Rust の仕事はバイト列を左右へ流すことに尽きる。

`project-setup.md` の「Rust と capabilities」節も同時に更新する。

## 3. レイアウト

### 決定4: 右ペインは横分割でエディタを押しのける。左のファイル一覧も畳めるようにする

```
┌──────────────────────────────────────────────────────┐
│ facet [フォルダ] [元に戻す] … [◧ 一覧] [◨ Claude]    │
├───────┬───────────────────────┬──────────────────────┤
│ファイル│                       │ [Claude 1 ✕][C 2 ✕] ＋│
│一覧    │   シーケンス図        │──────────────────────│
│        │                       │ $ claude             │
│(畳める)│                       │ > 用語を登録して     │
└───────┴───────────────────────┴──────────────────────┘
                                ↑ ドラッグで幅を変える
```

オーバーレイ（エディタの上に被せる）を採らないのは、**キャンバス系ツールの図の右端が黙って視界から消える**ため。押しのければ図はその幅でレイアウトし直され、見えているものが全部になる。

初期ウィンドウは 1280px、ファイル一覧が 256px（`project-setup.md`）。右ペインを開くとエディタの作業幅が目に見えて減るので、**ファイル一覧を畳めるようにして 256px を返せる**ようにする。畳みトグルはヘッダに置く（ボタン2個）。

ヘッダの `◨ Claude` は `projectDir === null` のとき無効。作業ディレクトリが決まらないため。

### 決定5: ペイン幅は `src/core/column-resize.ts` を再利用する

幅1要素の配列として `useColumnResize` に渡す。ポインタキャプチャ・キーボード（←→）・ダブルクリックで既定へ戻す・エディタが潰れない上限クランプが、すべて既存実装から得られる。

**3本目のリサイズ実装を生やさないこと**が理由。`open-issues.md` は既にキャンバス土台の丸ごと複製を「小さな負債」として抱えており、同じ形を増やさない。

`column-resize.ts` の説明が「表の列幅」に限定されている（「表を持つツールはこのモジュールを使う」）ので、**額縁のペイン幅もここを通ることを先頭コメントに書き足す**。

### 決定6: 畳んでもアンマウントしない

畳む＝CSS で隠すだけ。アンマウントすると xterm のスクロールバックが消え、プロセスの寿命（決定12）とも食い違う。非アクティブなタブも同じ扱い（全タブの xterm を常時マウントしておき、アクティブなもの以外を隠す）。

**隠している間 xterm は寸法を測れない**（`display:none` で `clientWidth` が 0）。開き直した瞬間・タブを切り替えた瞬間に **fit → `pty_resize` を1回走らせる**。これを落とすと「開き直したときだけ表示が崩れる」という、原因の分かりにくい壊れ方をする。

## 4. PTY レイヤ

### 決定7: PTY は Rust に持たせる（`portable-pty`）

「本物の端末」（Claude Code の TUI がそのまま出る、許可プロンプトもスラッシュコマンドも使える）が要件なので、`tauri-plugin-shell` の stdout ストリームでは足りない。Claude Code は raw mode の TUI であり、PTY が無いと描画も入力も成立しない。

Node のサイドカー（`node-pty` ＋ WebSocket）も検討したが採らない。ロジックが TypeScript に寄る利点より、**Node ランタイムの同梱・ネイティブモジュールのビルド・ローカルポートの開放**という代償が大きい。「Rust を書かない」ために全体の複雑さを増やす取引になる。

**Rust（`src-tauri/src/pty.rs`、コマンド4本）**

| コマンド | やること |
| --- | --- |
| `pty_spawn(program, args, cwd, cols, rows, channel)` | PTY を開いて子を起動し、セッション ID を返す |
| `pty_write(id, data)` | キー入力を書き込む |
| `pty_resize(id, cols, rows)` | 端末サイズを伝える |
| `pty_kill(id)` | 子を殺して後始末する |

セッションは `Mutex<HashMap<u32, …>>` を `tauri::State` で持つ。出力は専用スレッドが master の reader を読み、**Tauri v2 の `Channel` で生バイトのまま**フロントへ渡す。

**バイト列のまま渡すこと。** Rust 側で `String::from_utf8` すると、読み取りの区切りがマルチバイトの途中に落ちたときに**日本語が化ける**。xterm.js の `write()` は `Uint8Array` を受け取り UTF-8 の境界跨ぎを内部で繋ぐので、**デコードは xterm に任せる**。

**フロント**

| ファイル | 役割 |
| --- | --- |
| `src/fs/pty.ts` | `invoke` と `Channel` の薄いラッパ。既存の「`src/fs/*` が Tauri 境界」という流儀に合わせる |
| `src/core/terminal/sessions.ts` | タブの台帳。純関数＋I/O 注入（`app-controller` と同じ作り）。連番の採番・開く・閉じる・アクティブ切替・一括終了をここに閉じる |
| `src/components/TerminalPane.tsx` | ペインの枠とタブバー |
| `src/components/TerminalTab.tsx` | xterm 1本と PTY 1本の対応 |

### 決定8: タブ名は連番固定

初期状態が `Claude 1` / `Claude 2`。リネームは作らない。

**会話の内容からタブ名を自動で付けることは 4章 違反**（決定1）——facet が Claude の出力を読んで解釈することになる。タブ名は「facet が知っていること」だけで決まらねばならず、facet が知っているのは開いた順番だけである。

### 決定9: `claude` の起動可否を実装計画の第1タスクにする

実行ファイルの形が環境で違う。検証機では `C:\Users\<ユーザー名>\.local\bin\claude.exe`（ネイティブ実行ファイル）だが、npm 経由で入れた環境では `claude.cmd` になる。`portable-pty` の `CommandBuilder` が Windows の `PATHEXT` 解決までやるかは実機で確認するまで分からない。

**実装計画の第1タスクを「PTY で `claude` が1本立ち上がり、キーが届き、出力が出ること」にする。** 通らなければ `cmd.exe /c claude` へ一段落とす。ここが通らないと以降の全タスクが無意味になるので、先に潰す。

## 5. Skill の同梱と同期

### 決定10: `.claude/skills/` をアプリに同梱し、タブを作る直前に毎回同期する

**この決定が無いと機能の目的が達成できない。** Skill は facet リポジトリの `.claude/skills/` にあり、ユーザーが開くプロジェクトフォルダ（例 `sample-project/`）には入っていない。作業ディレクトリをプロジェクトフォルダにして `claude` を起動しても、プロジェクトレベルの Skill が見つからず**用語登録 Skill が使えない**。

**同梱**: `.claude/skills/` を Tauri の `bundle.resources` に入れる（`src-tauri/tauri.conf.json` に `"../.claude/skills/"`）。リポジトリを持たない人に配っても Skill が付いてくる状態にする。

**同期のタイミング**: タブを新規に作る直前に毎回。Skill の更新・追加が黙って取り残されないようにするため。

**同期の範囲**: **facet が同梱する Skill 名のディレクトリだけ**を消して、resources から置き直す。同梱名の一覧はアプリが持つ（現在は `glossary-term-register` と `error-catalog-register` の2本）。

範囲を絞る理由は、`.claude/skills/` を丸ごと消すと**ユーザーが自分で置いた Skill も消える**ため。ユーザーのフォルダを facet が破壊してよい範囲は、facet が書いたものに限る。

**Git への影響**: コピーされた `.claude/skills/` はユーザーのプロジェクトの Git に乗る。毎回同じ内容を書くので、facet 側の Skill を更新しない限り diff は出ない。チームで Skill を共有できる副次効果がある。

**capabilities を必ず確認すること。** `project-setup.md` が「新しい Tauri の JS API を使うたびに確認しないと**実行時に静かに動かない**」と警告し、既に3回踏んでいる。今回増えるのは resources の読み取り（`$RESOURCE` スコープ）と、プロジェクトフォルダ配下の `mkdir` / `remove`。

## 6. キーボードの境界

### 決定11: 端末ペインは操作言語の管轄外とする

**いま手を入れないと確実に壊れる箇所がある。** `App.tsx` のグローバル `keydown` は window の bubble 段階で `Ctrl+Z` / `Ctrl+Shift+Z` を横取りして `preventDefault` する。xterm の入力は隠し textarea の中で起きるので、**端末で `Ctrl+Z` を押すと facet が Undo する**——Claude Code には届かず、編集中の図が勝手に巻き戻る。

`rev 10章` がモーダルについて言っている「操作言語を停止する」と同じ扱いを端末ペインにも与える。実装はグローバルハンドラの先頭で、イベントの発生元が端末ペインの中かを見て早期 return する。**判定はペインの ref から読む**——window リスナーはマウント時に1回しか張らないため（`modalOpenRef` と同じ理由。state 直読みに「簡潔化」すると常に初期値になる）。

`rev 10章` にこの境界を書き足す。

**帰結として残る穴**: フォーカス脱出のショートカットは作らない。xterm は `Tab` を消費するので、**一度端末をクリックするとキーボードだけでは本体へ戻れない**（マウスで本体をクリックする必要がある）。facet は入力速度最優先（`rev 2章`）を掲げているので体験としては未達だが、キーの割り当てを増やさない判断を優先した。**完了時に `open-issues.md` の「挙動の穴」へ記録すること。**

## 7. ライフサイクル

### 決定12: 畳んでもプロセスは生きる。フォルダ切替では確認して終了する

| 出来事 | 挙動 |
| --- | --- |
| ペインを畳む | プロセスは生きたまま。CSS で隠すだけ（決定6） |
| タブの ✕ | その PTY を殺す。確認は出さない |
| **フォルダを切り替える** | **実行中のタブがあれば確認ダイアログを出し、承認されたら全タブを終了する** |
| アプリを閉じる | 既存の close 横取り（`interceptClose` → `controller.requestClose`）の経路で全 PTY を殺す |

畳む＝隠すだけにするのは、**会議中の誤操作で会話を失わない**ため（VSCode のターミナルと同じ振る舞い）。

タブの ✕ に確認を出さないのは、会話が Claude Code 側に残り `--resume` で戻れるため。

フォルダ切替で全終了にするのは、**作業ディレクトリがプロジェクトフォルダに固定されている**ため。残すと「別フォルダを見ている Claude」が古い cwd のまま画面に居座り、Skill も新しいフォルダ側に置かれるので、画面が嘘になる。確認ダイアログは既存のモーダルキューと `ConfirmDialog` にそのまま乗る（新しい仕掛けは要らない）。

## 8. エラー処理

### 決定13: 出す場所は「誰の状態か」で決める

facet の既存の使い分け（**バナー＝いま続いている状態／トースト＝起きた出来事**）に従う。タブ固有の状態は、そのどちらでもなく**タブの中**に出す。

| 起きること | どこに出すか |
| --- | --- |
| `claude` が見つからない／起動に失敗 | **そのタブの中**。タブ固有の状態なので、バナーにもトーストにも出さない |
| 子プロセスが終了した | **そのタブの中**に「終了しました（コード N）」。タブは残す |
| PTY への書き込み・リサイズが失敗 | 同上 |
| Skill の同期に失敗 | **トースト**で警告し、**起動は続行する**（Skill が無くても端末は使える） |

Skill 同期の失敗で起動を止めないのは、端末が開くこと自体には価値があるため。止めると「Skill のコピーに失敗したので Claude Code が開けない」という、利用者から見て理不尽な失敗になる。

## 9. テスト

| 対象 | 何を固定するか |
| --- | --- |
| `src/core/terminal/sessions.ts` | 純関数の単体テスト。連番の採番、開く／閉じる、アクティブ切替、フォルダ切替での一括終了 |
| Skill 同期 | I/O 注入で単体テスト。**同梱名のディレクトリだけを消すこと**と、**ユーザーが置いた Skill を消さないこと** |
| `TerminalPane` の DOM テスト | タブの追加・切替・✕、**畳んでもアンマウントしないこと**、開き直しで `pty_resize` が1回走ること |
| **App レベルの DOM テスト（新規）** | **端末にフォーカスがある間 `Ctrl+Z` が Undo を起こさないこと** |
| Rust | テストは書かない（判断を持たないため）。担保は実機確認 |

**xterm と `src/fs/pty.ts` はモックする。** xterm は canvas を使うので jsdom では正しく動かない。

**App レベルの DOM テストは既存の残件を1つ潰す。** `open-issues.md` は「`Ctrl+Z` / `Ctrl+Shift+Z` をエディタが消費しないことを守るテストが、リポジトリのどこにも無い」を「**全ツールの Undo が同時に静かに壊れうる唯一の穴**」と記録している。本マイルストーンはまさにその層（額縁のグローバル `keydown`）に触るので、この機会に1本立てる。**完了時に `open-issues.md` から該当項を消すこと。**
