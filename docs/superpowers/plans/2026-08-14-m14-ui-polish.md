# M14 UI 整理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 額縁・サイドメニュー・各ツール画面の見た目と動線を整える——ヘッダーが狭いウィンドウで見切れる欠陥を塞ぎ、文字ボタンをアイコンへ寄せ、「クリックして開始」の空状態を廃止し、操作ヒントを Windows / macOS で出し分ける。

**Architecture:** 3層に分けて入れる。(1) 額縁（`src/App.tsx` / `src/components/FileList.tsx`）——レイアウトとアイコン。(2) 共通部品——`ToolModule` にアイコンを1点追加し、操作ヒントを `KeyHints` として1本立てる。(3) 各ツール——空状態の廃止は `createEmpty` が最初の1件を持つ形にし、マウス動線はツールバーの常時表示で担保する。シーケンスの行高バグ（問いラベルの高さを勘定に入れていない）はレイアウトの入力を直して塞ぐ。

**Tech Stack:** React 19 / TypeScript / Tailwind v4 / lucide-react（既存依存。`PanelLeft` `PanelRight` `Plus` `X` を既に使用）／ vitest + @testing-library/react。**新規依存は無し。**

**Spec:** 別ファイルの spec は作っていない。設計は本ファイルの「確定した設計判断」に畳み込んである（合意の経緯は M14 の会話。反映先は完了時に `docs/overview-rev.md` 6章・9章）。

## Global Constraints

- **色値・フォントサイズを直書きしない**（`src/styles/conventions.test.ts` が走査して落とす）。役割トークン（`text-ink` / `text-ink-muted` / `border-rule` / `bg-surface` / `bg-canvas` / `text-warning`）と Tailwind のサイズ階級だけを使う
- **facet のパレットに `destructive` 役割は無い。** 赤は `warning`（Ember Fault）1本。削除の赤も `text-warning` を使う
- **アイコンだけのボタンには必ず `aria-label` を付ける。** DOM テストは role とアクセシブル名で引くので、名前を変えるとテストが落ちる。既存の `aria-label` は文言を変えない
- **`buttonBase`（`src/components/button-styles.ts`）を通す。** 生の `<button>` を新設するときは必ず敷く。自前のレイアウトを持つボタン（縦積み・flex-wrap）だけが対象外
- **1操作1コミット。** 構造操作の `onChange` は `mergeKey` に `null` を渡す（rev 10章）
- **`layout.ts` / `measure.ts` / `questions.ts` は純関数のまま保つ。** DOM を触らない
- 新規ファイルの日本語コメントは既存の密度に合わせる（「なぜそうしたか」を書き、「何をしているか」は書かない）
- 各タスクの最後に `npm test && npx tsc -b && npm run lint` が緑であることを確認してからコミットする

## 確定した設計判断

| # | 判断 | 理由 |
| --- | --- | --- |
| 1 | ヘッダーで伸縮を引き受けるのは1要素だけにし、左右の操作群は `shrink-0` で固定する | flex アイテムの既定は `min-width:auto`（内容幅より縮まない）。長いパスが右端の操作を画面外へ押し出していた |
| 2 | フォルダパスはヘッダーから**ファイル一覧の直上**へ移す | ヘッダーの幅を食う最大の要素であり、かつ「どのフォルダのファイル一覧か」の説明としてはサイドメニューの方が近い |
| 3 | ツール固有アイコンは `ToolModule` に持たせる（`FileList` に type→icon のマップを置かない） | マップを置くとツールが増えたとき直す場所が2つになる。`ToolModule` は既に `Editor` を持ち UI 依存が入っている |
| 4 | `ToolModule.icon` の型は `ComponentType<{ className?: string }>` とし、`LucideIcon` を書かない | `src/core/` を lucide に依存させないため。lucide のアイコンはこの型に代入できる |
| 5 | 最初の1件は `createEmpty` が持つ。エディタが開いた瞬間に自動で足すことはしない | 開いただけで自動保存が走り、Undo 履歴の起点がずれるのを避ける |
| 6 | 既存の0件ファイルの救済は「ツールバーの常時表示」（シーケンス）と「0件のときだけ出る追加ボタン」（ロジックツリー）で行う | 空状態を消しただけだと、0件の既存ファイルがマウスで操作不能になる |
| 7 | 操作ヒントの修飾キーは `$mod` / `$alt` のプレースホルダで書き、描画時に解決する | `Ctrl` 直書きは macOS で嘘になる。解決の口を `hint-text.ts` の1箇所に閉じる |
| 8 | 問いラベルの測定には **`text-xs` 用の見本要素を別に立てる** | 既存の測定器は `text-sm`。それで `text-xs` を測ると高さを1.4倍ほど過大に見積もり、行が無駄に伸びる。「測定と描画は同一の情報源を見る」（rev 9章）に従う |
| 9 | ロジックツリーに常設のツールバーは作らない | 「マウスだけでノードを増やせない」は M14 以前からある別の穴。ここで動線を発明すると、フォーカス中ノードの管理という新しい状態が要る。`docs/open-issues.md` に記録して切り離す |

```tsx
          title={props.projectDir}
        >
          <Folder aria-hidden className="size-3.5 shrink-0" />
          {/* 末尾（フォルダ名）の方が手がかりになるので、頭を省く */}
          <span className="min-w-0 flex-1 truncate text-left" dir="rtl">
            {props.projectDir}
          </span>
        </div>
      )}
      {props.files.length === 0 ? (
        <p className="p-4 text-sm text-ink-muted">
          このフォルダに JSON ファイルがありません。上のボタンで作成できます。
        </p>
      ) : (
        <ul>
          {props.files.map((file) => (
            <FileRow
              key={file.path}
              file={file}
              selected={file.path === props.selectedPath}
              onSelect={() => props.onSelect(file)}
              onDelete={() => props.onDelete(file)}
            />
          ))}
        </ul>
      )}
    </div>
  )
```

**`dir="rtl"` は「長いパスは頭でなく末尾を残す」ためのもの。** `truncate` は既定で末尾を省くので、そのままだとフォルダ名（一番知りたい部分）が消える。

```ts
/**
 * 操作ヒントの文字列（rev 10章の表示側）。
 *
 * **ヒントに `Ctrl` と直接書かないこと**——Tauri は macOS でも動くので、
 * 直書きは画面の上で嘘になる（キーの解釈側は `isPrimaryModifier` が
 * 既に抽象化しており、表示側だけが取り残されていた）。
 * プレースホルダの解決口はこの関数1つに閉じる
 */
import { altModifierLabel, primaryModifierLabel, type Platform } from './platform'

/** 操作ヒント1件。`keys` は `$mod`（Ctrl / Cmd）・`$alt`（Alt / Option）を含みうる */
export interface KeyHint {
  keys: string
  label: string
}

export function formatHintKeys(keys: string, platform: Platform): string {
  return keys
    .replace(/\$mod/g, primaryModifierLabel(platform))
    .replace(/\$alt/g, altModifierLabel(platform))
}
```

```tsx
  const labelMeasurerKey = `${labelFont.font}|${labelFont.lineHeight}|${fontGeneration}`
  const labelMeasurerRef = useRef<{

    measure: MeasureWidth
    cache: Map<string, WrappedBlock>
  } | null>(null)
  if (labelMeasurerRef.current === null || labelMeasurerRef.current.key !== labelMeasurerKey) {
    labelMeasurerRef.current = {
      key: labelMeasurerKey,
      measure: createSeqMeasurer(labelFont),
      cache: new Map(),
    }
  }
  const labelMeasurer = labelMeasurerRef.current

  /**
   * 問いラベルの高さ。**ガターの行高はこれを勘定に入れる**——入れないと、
   * 長い問い（投げっぱなしの unknown）が次の行へ食い込む。
   * indent（ifExecuted）はラベル列を 16px 削るぶん折り返しが増える

    if (block === undefined) {
      block = wrapWithin(text, labelMeasurer.measure, labelFont.lineHeight, {
        maxWidth: QUESTION_LABEL_WIDTH - (indent ? GUTTER_INDENT : 0),
        minWidth: 0,
        insetX: 0,
        // GutterSlot のラベル列は py-1（上下 4px ずつ）
        insetY: 4,
      })
      if (labelMeasurer.cache.size >= MEASURE_CACHE_LIMIT) labelMeasurer.cache.clear()
      labelMeasurer.cache.set(key, block)
    }
    return block.height
  }
```
