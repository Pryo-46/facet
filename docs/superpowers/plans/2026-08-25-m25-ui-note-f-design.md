## 位置づけ

UI ノート（`docs/facet-UI設計ノート.md`）の実施優先順位 §8 の **優先7（D17・D18）と優先10（§1.1）**。優先 1〜6・9 は消化済み（帰属は §8 の実施状況の行）。優先7 の着手条件だった **U4（破線エッジの意味）は、実装が既に答えを持っている**——本書の決定3 がそれを言語化して閉じる。優先8（フォント同梱）は U1 未決のままスコープ外。

**設計は 2026-08-25 に人間と対話で確定した。** 対話で下された裁定は5つで、いずれも本書の決定の根拠になっている:

1. **別枠は見送りの件数だけを出す**（凍結中の問いの内訳・総数は出さない）。あわせて「要対応は見送り配下を含まない」旨の**簡単な注意書き**を添える
2. **§1.1 の残り（ネイティブ select の置換・角丸の統一）を M25 に含める**
3. グレーの「見送り N」チップは**押すと飛ぶ**（既存の帯の原則「数えるだけでなく、そこへ飛べる」と揃える）
4. **登録 Skill の報告にも「見送り N」の行を出す**（アプリと Skill は同じ言葉を出す規約）
5. 角丸は**2段＋円**（部品・セル＝`rounded-sm`／浮遊面＝`rounded-md`／意図した円＝`rounded-full`）で固定し、機械検査で縛る
6. **帯の `⚠` 絵文字をやめて lucide アイコン（`CircleAlert`）にする。見送りチップにはアイコン（`StickyNoteOff`）を添える**（スペックのレビュー中に追加された指示。決定8）

## 着手前スキャンで確定済みの実態——指示文の前提を3つ検証した

M24 の教訓（「false なら設計をやり直す」と書ける前提は着手前に潰す）に従い、**設計の前に実物で確かめた。** 指示文自身が「未検証」と名指ししていた3点である。

1. **D17 の前提「見送り配下の未決が要対応に混じっている」は偽。** `poseQuestions`（`src/modules/issue-tree/derive.ts`）は抑制配下では問いを一切立てない（4種すべて——仮説なし・未決・保留・未判断が `!off &&` で消える）。`tallyQuestions` の doc も「立っている問いだけを数える（抑制された配下は勘定に入らない）」と明言している。**つまり D17 が警告した「単に外すと、そのノードは要対応から完全に消える」がまさに現状であり**、M25 の実作業は「外す」ではなく**消えている在庫を別枠として見えるようにすること**だけである。D17 の明記どおり**データ構造の変更は不要**。
2. **D18 は完全に実装済み。** `suppressedIssueIds`（`derive.ts`）が祖先を遡る導出そのもので、フィールドは持たず、循環でも止まらない。仮説検証モジュール設計ノートの D3 にも同旨がある。**残る作業は UI ノート側の文書固定だけ**（決定2）。
3. **U4 は実装が明確な答えを持つ。** `IssueTreeEdges.tsx` の破線は別種の参照ではなく通常の親子エッジで、「祖先の見送りで抑制された配下へ入る線」だけが破線になる（`SUPPRESSED_DASH = '4 3'`、色は `stroke-rule` のまま）。見送りを掲げた当の箱へ入る線は実線（M3 で一度退行させた経緯ごとコメントに記録済み）。

§1.1 側の実態も確定している:

- **ネイティブ `<select>` は2箇所**——用語集の種別列（`GlossaryEditor.tsx:367`）とエラーカタログの対応レベル列（`ErrorCatalogEditor.tsx:267`）。どちらも `appearance-none`＋自前の矢印 SVG で**閉じた状態の見た目は既にカスタム**であり、ネイティブのまま残っているのは**開いたときの選択肢リスト**（OS 描画）だけ。どちらも `arrowsOwnedByField: true` で**素の ↑↓ が閉じたまま値を切り替える**——この打鍵は操作言語の一部である。
- **角丸は実質2系統に割れている。** アプリ側のコードは `rounded-sm`（Tailwind v4 で 4px）が基調で、同値の裸の `rounded`（4px）が5箇所前後、意図した円の `rounded-full` が数箇所。一方 shadcn 由来の `src/components/ui/` は `rounded-lg`（8px。`button.tsx`・`dropdown-menu.tsx` の面）・`rounded-md`（6px。メニュー項目）・`rounded-xl`（12px。`alert-dialog.tsx`）・任意値 `rounded-[min(var(--radius-md),10px)]` が混在する。**UI ノート §1.1 の「角丸半径が全て異なる」の実体はこの ui/ とアプリ側の割れである。**

## 決定1: 別枠「見送り N」——集計は `derive.ts`、描画は帯の隣、Skill も同じ言葉

### 集計（導出1本）

`derive.ts` に **`deferredIssueCount(issues)`**——`events` が空でない課題の数（＝見送りを掲げた課題の数）——と、その表示文言・行の組み立てを足す:

- ラベルは定数として1箇所に置く（`QUESTION_LABELS` / `TALLY_TOTAL_LABEL` と同じ扱い。語は `見送り`）
- **行の組み立て関数**（`deferralLine(n)` の形。`見送り N`。0件のときの扱いは `tallyLine` の流儀に合わせて計画で確定）を置き、**アプリのチップと Skill の報告が逐語で同じ文字列を出す**

数えるのは**課題ノード自身が見送りを掲げている数**である。課題のイベントは見送りしか無い（スキーマ）ので判定は `events.length > 0`（＝`latestKind !== null`）。入れ子の見送り（見送り配下でさらに見送りを掲げた課題）も**それぞれ1と数える**——「誰が何を落としたか」の台帳なので、掲げた事実の数がそのまま在庫の行数である。

**凍結中の問いの内訳・総数は出さない**（人間の裁定1）。導出しようと思えば `poseQuestions` を抑制なしで回せば得られるが、**使う画面が無い導出関数は作らない**——使用0件のものを残さない M24 と同じ判断。必要が出たときに足すのは安い。

### 描画（グレーのチップ、帯の隣）

`IssueTreeEditor` の帯で、既存の `<MissingTally>` の**隣**に `badgeClass('deferred')`（`border-rule bg-surface-muted text-ink-muted`——rev 9章の見送りの描き方そのもの）のボタンを置く。文字の前に `StickyNoteOff` のアイコンを添える（決定8）。0件なら描かない（「押しても行き先が無いボタンを置かない」——`MissingTally` と同じ理由）。

**`MissingTally` 部品そのものは触らない。** 部品の `parts` は「`total` の内訳」という契約であり、見送りは `total` の**外**にある別枠なので、`parts` に混ぜると「合計と内訳が合わない帯」になる。D17 の求める「別枠」は視覚的にも構造的にも帯の外に置くのが正しい。

**押すと飛ぶ**（裁定3）: 押すたびに次の「見送りを掲げた課題」の箱へ視点が移り、巡回する。既存の `goToNextOpen` と同じ機構に載せる（対象の列挙が `listOpenTargets` に足せるか、別の列挙が要るかは計画の着手前スキャンで確定——決定6）。`aria-label` は `MissingTally` のチップの形（`次の${label}へ`）に合わせる。

**注意書き**（裁定1）: チップの `title` に1文——「見送り配下の問いは要対応に数えません」の趣旨——を載せる。画面に常時テキストを足す形は採らない（帯を長くするだけで、読む必要が生まれるのは「なぜ数が合わない？」と思った瞬間だけ）。あわせて **`docs/missing-semantics.md`（U3 の規約文書）に明文化する**（決定7）。

### Skill（裁定4）

`issue-tree-write.mjs` の報告（現在 `tallyLine` を1行出している `:303` 付近）に `deferralLine` を1行足す。`derive.ts` は**バイト一致コピー**（`.claude/skills/issue-tree-register/scripts/derive.ts`）なので、変更後に `cp` で更新する——手で写さない（`skill-copy.test.ts` がバイト一致を強制する）。**smoke テスト（`src/modules/issue-tree/skill-write.smoke.test.ts`）の逐語一致の検査に新しい行も含める**——「集計結果の逐語一致も固定する」規約（rev 4章）の適用対象がそのまま1行増える形。

## 決定3: U4 の決着——破線エッジの言語化

実装から取った答えを UI ノートに書いて U4 を閉じる。言語化はこうである:

> **課題ツリーのエッジはすべて親子関係である。別種の参照を表すエッジは存在しない。** 破線は関係の**種類**ではなく抑制の**状態**を運ぶ——「祖先の見送りで抑制された配下へ入る線」だけが破線になり（色・濃さは `stroke-rule` のまま、線の切れ方だけで区別する）、**見送りを掲げた当の箱へ入る線は実線のまま**である。見送りはそこで下した判断の表明であって「もう見なくてよい枝」ではない、という語彙（仮説検証モジュール設計ノート）の視覚版。

反映先は3箇所——U4 の項（答えを書いて「決着」の見出しに）、§5「課題ツリー」の未確認事項（破線の項を解消）、§8 の着手条件の表（優先7 の前提が満たされたこと）。D18 の未確認事項の段落も同時に解消する（決定2）。

**U4 が「確認できない」とした心配——親子と参照が同じ視覚チャネルで混同される——は、参照が存在しない以上、起きない。** これが「問いとして閉じている」の中身である。

## 決定4: ネイティブ select の置換——既存 DropdownMenu を使い、↑↓ の操作言語を守る

対象は2箇所（用語集の種別列・エラーカタログの対応レベル列）。**新しい shadcn Select は導入せず、既にある `DropdownMenu`（Radix）を使う。** 根拠は2つ:

1. **先例がある。** 課題ツリーの判断ピッカーが同じ形（素の button トリガー＋ `DropdownMenuContent`）で動いており、`onCloseAutoFocus` の抑止・メニュー項目のサイズ（M23 決定8 で 14px 据え置きが実機確認済み）という知見が蓄積済み。部品を1種類に保てば角丸統一（決定5）の対象も増えない。
2. **キー処理を完全に所有できる。** トリガーが素の `<button>` なので、「**閉じたまま ↑↓ で値を切り替える**」という現在の操作言語を、ライブラリのキー横取りと戦わずに維持できる。Radix Select を使う案は「トリガーの ArrowDown を preventDefault で横取りできるか」という**未検証の前提**を持ち込む——M24 の教訓（前提は着手前に潰す）に照らし、**前提そのものが発生しない側**を採る。

### キーボード契約（不変条件）

- **閉じたまま ↑↓ ＝ 値切り替え**（現状の `arrowsOwnedByField: true` の挙動を維持）
- **開く打鍵は、現在のネイティブ select で開く打鍵に合わせる**（Windows なら Space / Alt+↓ が通説だが、**通説のまま計画に書かない**——現在の `onCellKeyDown` の契約（`editing: false` ほか）とどの打鍵が衝突しないかも含め、計画の着手前スキャンで実測して確定する。決定6）
- セル移動の操作言語（Tab・Alt+↑↓ ほか `onCellKeyDown` が受けるもの）・`aria-label`・`data-cell` は据え置く

### 見た目

トリガーは現在の閉じた select と同じ（`cellInput` のクラス＋自前の矢印 SVG——**セルに見えること**が要件で、ボタンに見えてはいけない）。開いたリストは `DropdownMenuContent` で、現在値の項目に印を付ける（判断ピッカーの流儀に合わせる）。

### テスト

DOM テストで押さえる: 閉じたまま ↑↓ で値が変わり `updateTerm` / `updateLevel` 相当の onChange が走ること・開いて項目を選ぶと値が変わること・Esc で閉じて値が変わらないこと・開いている間のフォーカスの戻り（`onCloseAutoFocus` の抑止が要るかは判断ピッカーの実装に倣う）。

## 決定5: 角丸の規約——2段＋円、許可リストの機械検査で固定

### 規約

| 段 | 値 | 対象 |
| --- | --- | --- |
| `rounded-sm` | 4px | **部品・セル・チップ・バッジ・ボタン**——面の中に置かれるもの全部 |
| `rounded-md` | 6px | **浮遊面**——ポップアップ層に浮かぶ面（メニューの面・ダイアログ） |
| `rounded-full` | 円 | **意図して円のもの**だけ（トグルのつまみ・ドット） |

方向付き（`rounded-b-*` 等）は値サフィックス必須（`rounded-b-md` は可、裸の `rounded-b` は不可）。**裸の `rounded`（4px）は禁止**——`rounded-sm` と同値だが、同じ半径に2つの綴りがあると「揃っているか」が字面から読めない。任意値 `rounded-[...]` も禁止。

**機械検査が守るのは「この3語（＋方向付き）以外が現れない」ことだけである。** `sm` と `md` の使い分けの当否（この面は部品か浮遊面か）は機械では判定できない——そこはレビューと実機が守る。`conventions.test.ts` に M23 の `leading-*` 許可リストと同じ形で足し、**走査の母集合はディレクトリで取る**（`src/` 配下全部。**`src/components/ui/` を除外しない**——違反の現場がまさに ui/ にある。既存検査の `EXCLUDED` の扱いは計画で確認する）。

### 変更点の仕分け

- **見た目が変わらない正規化**（4px→4px の綴り替え）: 裸の `rounded` → `rounded-sm`（`badge-styles.ts:30`・`HypothesisRow.tsx:245`・`IssueTreeEditor.tsx:169,189,198`）
- **見た目が変わるもの**: `ui/button.tsx` の `rounded-lg`（8px）と任意値 → `rounded-sm`（4px）／`ui/dropdown-menu.tsx` の面 `rounded-lg` → `rounded-md`（6px）・項目 `rounded-md` → `rounded-sm`／`ui/alert-dialog.tsx` の `rounded-xl`（12px） → `rounded-md`・`rounded-b` → 方向付きの値ありへ
- `Toast`（現在 `rounded-sm`）は**触らない**——fixed 配置だが実機で違和感の報告が無く、規約上も許可リスト内。sm→md へ動かすかは実機で見てから

全出現の確定は計画の着手前スキャンで行う（決定6。`.tsx` だけでなく `.ts` も——`badge-styles.ts` が現に `.ts` である）。

## 決定8: 帯の `⚠` をアイコンへ——ただし端末に出る文字列は絵文字のまま

**帯（`MissingTally` 部品）の `⚠` を lucide の `CircleAlert` に置き換える。** 部品は全5モジュール共通なので、一度の変更で全部の帯が揃う。**`tallyLine`（`core/missing-tally.ts` / `issue-tree/derive.ts`）の `⚠` は変えない**——これは Skill が端末に出す文字列で、SVG アイコンは出せない。端末では `⚠` がそのまま有効に働く。

- **アイコンの色は役割トークンで明示する。** `⚠` 絵文字は OS のカラー絵文字で描かれ、**色が rev 9章「色を持つのは意味だけ」の管理の外にあった**——アイコン化はこの穴も塞ぐ。警告は欠落軸の合図なので **`text-missing`** を当てる（総数の文字は現状どおり `text-ink-muted` のまま。色を持つのはアイコンだけ）。実機で「うるさい」と出たら `ink-muted` へ落とす判断は残す
- **大きさは帯の文字（`text-base` 16px）に揃える。** lucide の既定 24px をそのまま置かない
- **0件のときはアイコンも出さない**（現状 `⚠` を付けない流儀と同じ）
- **見送りチップ（決定1）には `StickyNoteOff` を添える**——「付箋を外す＝棚上げ」のメタファ。大きさはチップの文字（`text-sm` 14px）に揃える。lucide には `Archive`（D17 の「倉庫にしまう」のメタファ）もあり、実機で StickyNoteOff が読み取れなければ差し替える。どちらも実在は `node_modules/lucide-react` で確認済み
- **「帯と `tallyLine` の `⚠` を同じ字面で縛る」テスト（issue-tree-m3 の fix wave）は意図的に分岐させる。** 縛りたかったのは「アプリと Skill が同じ言葉を出す」ことで、語（`要対応` ほか `QUESTION_LABELS`）の一致は `toMissingTally` 経由で保たれ続ける——`⚠` だけが「画面はアイコン・端末は絵文字」に分かれる。この分岐を新しい形で縛り直す（帯側は `CircleAlert` の存在を、行側は `⚠` を、それぞれ検査する）

`⚠` の全出現は着手前スキャンで再確認するが、本書の時点の実測では**実体3箇所**（`src/components/MissingTally.tsx:28`・`src/core/missing-tally.ts:33`・`src/modules/issue-tree/derive.ts:221`）と**それを見るテスト**（`MissingTally.dom.test.tsx`・`core/missing-tally.test.ts`・`issue-tree/derive.test.ts`・`issue-tree/IssueTreeEditor.dom.test.tsx:616` 付近・`sequence/skill-write.smoke.test.ts`）である。**変えるのは `MissingTally.tsx` とその帯側テストだけ**で、`tallyLine` 系のテストは据え置く。

## 検証

実装後、人間が実機で一巡する。**このマイルストーンは見た目そのものが成果物**なので、チェックリストは `history/m25-core-ui-note-f.md` に空のまま写し、消し込みは `open-issues.md` の「次に手を付ける候補」が管理する。

1. 見送りを含むファイルで、帯に **`見送り N` のグレーチップ**が出る（`badgeClass('deferred')` の面。0件のファイルでは出ない）
2. チップを押すと**見送りを掲げた課題の箱へ視点が飛び**、繰り返し押すと巡回する
3. チップにホバーすると**注意書き**（要対応は見送り配下を含まない）が読める
4. **見送りトグルを切ると要対応の数が増える**（＝要対応が見送り配下を含まないことの逆向きの確認）
5. 用語集の種別・エラーカタログの対応レベルで、**開いたリストが styled**（OS ネイティブのリストが出ない）
6. **閉じたまま ↑↓ で値が切り替わる**（従来どおり。開かずに切り替わること）
7. select 置換後も **Tab・Alt+↑↓ のセル移動が変わらない**（操作言語の据え置き）
8. ダイアログ・メニュー・ボタンの**角丸が2段に揃って見える**。とくにダイアログ（12px→6px）とボタン（8px→4px）が硬く見えすぎないか
9. ライト・ダークの両方で `見送り N` チップの文字が読める（`ink-muted` on `surface-muted`）
10. **帯の警告が絵文字でなくアイコン**（`CircleAlert`）で出ており、`text-missing` の色が5モジュールすべての帯でうるさく見えないか（うるさければ `ink-muted` へ落とす）
11. **見送りチップの `StickyNoteOff` が 14px の文字と揃って見え、何のアイコンか読み取れるか**（読み取れなければ `Archive` へ差し替える）
