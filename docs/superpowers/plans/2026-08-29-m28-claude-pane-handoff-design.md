# M28 設計: Claude Code ペインへのファイル受け渡しと右クリック

2026-08-29 / m28

## この文書の位置づけ

Claude Code ペインの操作性を2点直す設計。

1. **ファイルを Claude に渡す動線がない**（[issue #21](https://github.com/Pryo-46/facet/issues/21)）。
   いまはエクスプローラでパスをコピーして端末へ貼り付けている
2. **端末で右クリックすると WebView2 の既定メニューが出る**。端末としてはコピー／貼り付けが
   直接起きてほしい

ブレインストーミングでの決定と、その根拠になった調査結果を記録する。

---

## 1. 目的と範囲

**目的**: 「このファイルのことなんだけど」を、パスを手で写さずに Claude へ渡せるようにする。

依頼者が挙げた場面は3つある。

| # | 場面 | いまの回避策 |
| --- | --- | --- |
| 1 | ペインを開いたとき、**開いているファイルで会話を始めたい** | パスを打つ |
| 2 | 会話中に「**このロジックツリーに書いてあって〜**」とファイルを渡したい | エクスプローラでパスをコピー |
| 3 | **エクスプローラのウィンドウからポイっと渡したい** | 同上 |

**やらないこと**:

- Claude Code の IDE 連携プロトコルの実装（§8.1 で却下した理由を記録した）
- 会話の内容を facet が読むこと。**渡すのは参照だけ**で、ファイルの中身は Claude が自分で読む
  （rev 4章「facet は端末のホストであって AI の対話相手ではない」）
- 渡した直後に送信すること。**`Enter` は押さない**——参照を入力欄に置くだけにして、
  続きの文は人が打つ

---

## 2. 全体像 — 「差し込み口」は1本

3つの場面と右クリックの貼り付けは、**すべて同じ1本の口**に集約する。

```
  ┌─ 起動時: 選択中ファイル ──┐
  ├─ 一覧の @ ボタン ────────┤
  ├─ エクスプローラからD&D ──┤──▶ term.paste(文字列) ──▶ onData ──▶ 既存の send ──▶ PTY
  └─ 右クリック貼り付け ─────┘
```

### 2.1 `write()` ではなく `term.paste()` を通す

`ptyIo.write()` で PTY へ直接送らず、xterm の `term.paste(text)` を呼ぶ。理由は3つ。

- **bracketed paste（`ESC[200~` … `ESC[201~`）で囲まれる。** 「人が貼り付けた」のと同じ形で
  Claude Code に届く。`@` を打つと出るファイル検索のポップアップに文字列が食われる懸念が減る
  （**実機で確かめる**。§9.2）
- **既存の `send` をそのまま再利用できる。** `term.paste()` は `onData` を発火し、
  `TerminalTab` が登録済みの `send` に流れる。起動待ちのキュー（`pendingRef`）も
  書き込み失敗の表示も、何も足さずに効く
- **`ptyIo` を新しい場所から呼ばなくて済む。** PTY の ID を握っているのは `TerminalTab` の
  内側だけで、外に出すと「誰が生存を管理するのか」が増える

### 2.2 命令的 API（ref）は生やさない

`TerminalTab` は props だけで動く（M11 の設計方針）。外から差し込むために
`useImperativeHandle` を足すと、App がタブごとのハンドルを表で持ち、閉じたタブの
後始末をする責任が増える。

代わりに **`insertion: { seq: number; text: string } | null` を props で渡し、
`useEffect(..., [insertion?.seq])` で消化する**。

- `seq` は App が持つ単調増加の連番。**同じ指示が二度実行されない**
- 消化したことを親へ返す往復が要らない（`seq` が変わらない限り effect は再実行されない）
- 同じファイルを続けて2回渡す操作も、`seq` が進むので両方届く

App が持つのは `{ targetId: number; seq: number; text: string } | null` の1つだけ。
`TerminalPane` が `insertion.targetId === session.id` のタブにだけ渡す。

## 3. 渡す文字列（コア・純関数）

`src/core/terminal/file-reference.ts` に純関数を置く。React も Tauri も知らない。

```ts
/**
 * ファイルのパスを、端末へ差し込む参照文字列にする。
 * 末尾にスペースを付ける——続けて文が打てるようにするため
 */
export function fileReference(projectDir: string, filePath: string): string
```

### 3.1 プロジェクト配下は `@相対パス`、外は素の絶対パス

`claude` の cwd は `projectDir` なので、配下のファイルは相対パスで解決する。

```
projectDir = C:\Dev\Projects\facet
filePath   = C:\Dev\Projects\facet\docs\用語集.json
→ "@docs/用語集.json "
```

**プロジェクトの外のファイルには `@` を付けない**（エクスプローラから落とされたときに起きる）。

```
filePath = D:\会議資料\議事録.md
→ "D:\会議資料\議事録.md "
```

`@` は cwd 相対のファイル参照として作られており、Windows の絶対パス（ドライブレターの
コロンとバックスラッシュを含む）が `@` の後ろで解決する保証がない。**`@` を付けずに素の
絶対パスを本文に置けば、Claude は自分でそれを読みに行く。** 確実な方を採る。

### 3.2 区切りは `/` に揃える。ただし相対化の判定だけ正規化する

- 返す相対パスの区切りは `/`（`@docs/用語集.json`）。バックスラッシュは Claude 側で
  エスケープと解釈されうる
- **配下かどうかの判定は、`\`→`/` と小文字化で正規化してから前方一致**を見る。
  Windows のパスは大文字小文字を区別しないので、`C:\Dev\...` と `c:\dev\...` が
  別物になってはいけない
- **返す文字列には元の綴りを使う。** 判定のための正規化を出力へ持ち込まない

### 3.3 複数ファイルはスペース区切りで連結

エクスプローラは複数選択したままドロップできる（`payload.paths` は配列）。
各パスを変換してスペースで繋ぐ。**上限は設けない**——落とした人が落としたぶんだけ渡す。

## 4. トリガー1: 起動時の差し込み

### 4.1 台帳（`sessions.ts`）に初期テキストを持たせる

セッションごとに「起動したら1回だけ入れる文字列」が要るので、台帳に持つ。

```ts
export interface TerminalSession {
  // ...既存
  /** 起動直後に1回だけ差し込む文字列。無ければ null */
  readonly initialText: string | null
}

export function openSession(state: TerminalState, initialText: string | null): TerminalState
```

**`insertion` の仕組みには乗せない。** `insertion` は「いま動いているタブへ差し込む」もので、
起動時のそれは「PTY がまだ無い」段階の話。`send` のキューを当てにする形も採らない——
PTY へ直接書くと bracketed paste で囲まれず、§2.1 で得た性質を失う。

### 4.2 差し込むのは `spawn` が解決した後

`TerminalTab` の起動 effect の `.then` で、待ち行列（`pendingRef`）を流し切った後に
`term.paste(initialText)` を呼ぶ。

- **`disposed` で守る。** StrictMode で捨てられた側が差し込んではいけない
- **`hidden` は見ない。** 差し込みは表示に依存しない（`fit()` と違い、寸法を測らないため）

### 4.3 タイミングは実機で決める（§9.2 の検証タスク）

`claude` は起動に1秒前後かかり、TUI が入力を受け付ける前に書くと消える。M11 の記録には
「`claude` は起動直後に `ESC[6n` を送り、返事が来るまで描画を始めない」とある。

**まず `spawn` 解決直後に書く素朴版を実装し、実機で確かめる。** 消えるなら「最初の出力が
来てから N ms 静まったら差し込む」へ差し替える。この判断は机上ではできない。

### 4.4 「ペインを開く」も「＋」も同じ経路

`openTerminal(text?)` の1本にまとめる。省略時は**選択中ファイルの参照**を入れる。

- ヘッダの「Claude Code ペインを開く」→ 選択中ファイルが入る（場面1）
- タブバーの「＋」→ 同上。新しい会話も同じファイルから始まるのが自然
- 一覧の `@` ボタン（§5）→ **その行のファイル**を明示的に渡す

## 5. トリガー2: ファイル一覧の `@` ボタン

### 5.1 削除ボタンの左に置く。選択は動かさない

`FileList` の行は既に `<li className="flex items-stretch">` に「選択ボタン＋削除ボタン」が
並ぶ形なので、削除の左にもう1つ足す。アイコンは `AtSign`（`lucide-react`。人間の指定）。

```
┌─────────────────────────────────────────┐
│ 用語集.json                     [@] [🗑] │
│ エラーカタログ.json             [@] [🗑] │
│ 画面遷移.json          ●選択中   [@] [🗑] │
└─────────────────────────────────────────┘
```

**押しても選択状態は変わらない。** これが要点であり、この機能の主張そのものである——
編集中のファイルを開いたまま、別のファイルを Claude に渡せる。

> **タブバーに「今のファイルを渡す」ボタンを置く案は却下された**（人間の裁定）。
> 選択中のファイルしか渡せず、別のファイルを渡すには編集中のファイルを離れる必要が
> あるため。

`aria-label` / `title` は `${fullName} を Claude Code に渡す`。削除ボタンと同じく
**開けない・編集不可のファイルにも出す**（渡す先は Claude であって facet ではない）。

### 5.2 ペインが閉じていても押せる

押したときのふるまい:

1. `paneOpen` が false なら開く
2. タブが無ければ `openTerminal(参照文字列)`（§4 の経路にそのまま乗る）
3. タブがあれば `insertion` を進める（アクティブなタブが宛先）

**「ペインを開いてください」と拒む形にしない。** 押した人がやりたいのは「渡すこと」で、
ペインを開くのはその手段でしかない。

## 6. トリガー3: エクスプローラからのドラッグ＆ドロップ

### 6.1 `dragDropEnabled` は既定の `true` のまま

Tauri の設定スキーマにはこうある。

> Whether the drag and drop is enabled or not on the webview. By default it is enabled.
> **Disabling it is required to use HTML5 drag and drop on the frontend on Windows.**

つまり Windows では「Tauri のドロップイベント」と「HTML5 D&D」は排他である。

**facet は HTML5 D&D を1箇所も使っていない**（`src/` 全体で `draggable` / `dataTransfer` /
`DragEvent` / `onDragStart` / `onDrop` の該当が0件。仕切りのドラッグもキャンバスのパンも
ポインタイベントで実装されている）。したがって既定のままで失うものは無い。

> 検討時には「ファイル一覧から端末へ HTML5 D&D」も候補にあったが、それを採ると
> `dragDropEnabled: false` が必要になり、エクスプローラからのドロップが受けられなくなる。
> 一覧は同じウィンドウの中にあり `@` ボタンで代替できるが、エクスプローラからは
> D&D 以外の手段が無い。**外を採る。**

### 6.2 ドロップ位置がペインの中かを判定する

`getCurrentWebview().onDragDropEvent()` は**ウィンドウ全体で発火する**ので、位置で絞る。

- `payload.position` は**物理ピクセル**。`window.devicePixelRatio` で割って CSS ピクセルへ
- 既存の `terminalPaneRef`（`<aside>`）の `getBoundingClientRect()` と突き合わせる
- **ペインの外に落ちたものは無視する。** エディタ側にファイルを落とす意味は現状ない

DPI 換算は実機でしか確かめられない（§9.2）。

### 6.3 `over` の間はペインを強調する

`payload.type === 'over'` で位置がペイン内なら、`<aside>` に枠の強調を出す。
`leave` と `drop` で消す。

**これは省かない。** 何の反応も無いドロップ先は「落とせること」が分からず、機能が
発見されない。状態1つとクラス1つで済む。

### 6.4 落とした後は `@` ボタンと同じ

ペインを開き、タブが無ければ起動し、あれば `insertion` を進める（§5.2 と同じ経路）。

## 7. 右クリック

### 7.1 端末の中: メニューを出さず、1動作で済ませる

`TerminalTab` の端末ホスト要素に `onContextMenu` を置く。

```
preventDefault()                        ← WebView2 の既定メニューが消える
  ├ term.hasSelection() が真
  │    → clipboard.writeText(term.getSelection()) → term.clearSelection()
  └ 偽
       → clipboard.readText() → term.paste(text)   ← 空文字なら何もしない
```

Windows Terminal と同じ作法。**自前のコンテキストメニュー（「コピー／貼り付け」の2項目）を
出す案は採らない**——クリックが1回増えるだけで、選べるものは実質1つしかない。

`hasSelection` / `getSelection` / `clearSelection` / `paste` はいずれも
`@xterm/xterm` の公開 API（`typings/xterm.d.ts` で確認済み）。

### 7.2 ペインの他の場所: メニューを止めるだけ

タブバーで右クリックして貼り付けが起きるのはおかしい。`TerminalPane` の外枠に
`preventDefault()` だけのハンドラを置き、**何も起こさない**。

**アプリ全体では止めない**（人間の裁定）。エディタ側のテキスト欄では OS のメニューが
そのまま使え、右クリックからの貼り付け手段が失われない。

### 7.3 権限とエラーの扱い

- `capabilities/default.json` に **`clipboard-manager:allow-read-text` を追記する**。
  いまは `write-text` と `write-html` だけ。このファイルは `description` に理由を書く
  流儀なので、そこも更新する
- **Rust 側は増えない。** クリップボード読み取りはプラグインの権限、D&D は Tauri コアの
  イベントで、自前コマンドは5本のまま（rev 7章の例外一覧は変わらない）
- 失敗は握り潰さない（M11「握り潰すと原因が画面から読めない」）。`TerminalTab` に
  `onError(message: string)` を1本足し、App の既存トーストへ出す。
  **`session.message` は使わない**——あれは `exited` / `failed` の欄で、コピーの失敗で
  セッションを死んだ扱いにしてはいけない

## 8. 検討して採らなかった案

### 8.1 Claude Code の IDE 連携として名乗る

VS Code で `claude` を起動すると `In <ファイル名>` と表示され、開いているファイルが
自動で文脈に入る。調査したところ、これは拡張機能が

- `~/.claude/ide/<port>.lock` を書き（実測した中身:
  `{"pid":…,"workspaceFolders":["c:\\Dev\\Projects\\facet"],"ideName":"Visual Studio Code","transport":"ws","runningInWindows":true,"authToken":"…"}`）
- WebSocket サーバを立てて選択中ファイルを通知する

ことで実現している。facet が同じことをすれば、場面1が**操作なしで**成立し、ファイルを
切り替えれば表示も追従する。

**却下する。理由は3つ。**

- **公開仕様ではない。** Claude Code の更新で黙って壊れる。`open-issues.md` には既に
  「Miro のクリップボード形式が非公開で、Miro 側の変更で壊れうる」が載っており、
  同じ種類の負債をもう1本背負うことになる
- **場面3を賄えない。** エクスプローラからのドロップは IDE 連携の範囲外なので、
  結局この文書の仕組みも要る
- **上乗せされるのは「表示の追従」だけ。** 場面1〜3はすべて §2 の仕組みで成立する

まず本設計を出して実際に使い、「やはり追従が要る」となったときに別マイルストーンで
評価する。

### 8.2 ファイル一覧から端末への HTML5 D&D

§6.1 のとおり、エクスプローラからのドロップと排他になる。`@` ボタンで代替する。

### 8.3 タブバーの「今のファイルを渡す」ボタン

§5.1 のとおり、人間の裁定で却下。

## 9. テストと実機確認の線引き

M11 の教訓（「jsdom にレイアウトが無いために必ず通る、回帰検出力ゼロのテストは書かない」）に
従い、測れるものと測れないものを最初に分ける。

### 9.1 自動テストで固定するもの

**コア（vitest・純ロジック）**

- `fileReference`: プロジェクト配下 → `@相対パス␣` / 区切りが `/` になること /
  大文字小文字が違っても配下と判定されること / 返す文字列は元の綴りであること /
  プロジェクト外 → `@` が付かない絶対パスであること
- `openSession(state, initialText)`: `initialText` が載ること・`null` でも既存の主張が
  壊れないこと

**DOM（jsdom）**

- `insertion.seq` が変わったときだけ `term.paste` が呼ばれること。
  **同じ `seq` で二度呼ばれないこと**を明示的に主張する
- `insertion.targetId` と一致しないタブには差し込まれないこと
- ファイル一覧の `@` ボタンが `onHandoff(file)` を呼び、**`onSelect` を呼ばない**こと
  （選択を動かさないという主張そのもの）
- 端末ホストの `contextmenu` で `preventDefault` が呼ばれること／選択の有無で
  コピーと貼り付けが分岐すること
- ペイン外枠の `contextmenu` で `preventDefault` は呼ばれるが、クリップボードには
  触らないこと

### 9.2 実機確認へ回すもの

いずれも jsdom では測れない。**実機確認は人間が行う**（サブエージェントは Tauri の GUI を
操作できない）。

| # | 確かめること | ダメだったときの手 |
| --- | --- | --- |
| 1 | **起動時の差し込みが消えないか**（§4.3） | 「最初の出力から N ms 静穏」へ差し替え |
| 2 | **`@` がファイル検索のポップアップに食われないか**（§2.1） | `@` を外して素のパスにする |
| 3 | WebView2 の既定メニューが実際に消えること | — |
| 4 | エクスプローラからのドロップ位置判定（DPI 換算。§6.2） | 換算式を実測に合わせる |
| 5 | 複数ファイルを一度に落としたときの見え方（§3.3） | — |
| 6 | 右クリック貼り付けで日本語が化けないこと | — |
