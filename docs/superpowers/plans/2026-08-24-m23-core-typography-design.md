# M23 設計スペック: タイポグラフィスケール v2（UI ノート B——D11・D12・D13）

> **記録。** 書いた時点の判断をそのまま残す（M21 のスペックと同じ扱い）。実装で確定した差分は申し送り `docs/history/m23-core-typography.md` と rev 9章に出る。

## 位置づけ

UI ノート（`docs/facet-UI設計ノート.md`）の実施優先順位 §8 の **優先5**。A（色の規約）は M21・PR #7、C（未定義表現の本体）は M22・PR #8 でマージ済み。優先 1〜4・9 は消化済みで、B（タイポグラフィ。D11・D12・D13）が本マイルストーンである。

- **D11**: タイポグラフィスケールの固定（14px 下限・密度は行高で稼ぐ・小さくするなら薄くしない）
- **D12**: 表示環境（27型 WQHD・100% スケーリング＝約109 PPI）に基づく基準値の 16px 化。D11 の本文 16px の根拠であり、独立した作業項目ではない
- **D13**: ズームではなく基準値で解決し、ボーダーは 1px 固定（一部修正あり。決定7）

**設計は 2026-08-24 に人間と対話で確定した。** 判断材料として、実物のトークン・クラス・`sample-project` の実データを写した実寸比較モック（現行／提案を6ペアで左右比較。Artifact `https://claude.ai/code/artifact/56f7c808-3b12-4078-9432-039144f37796`）を 27型 WQHD・100% で人間が目視し、**カラム名の 16px 化とボタンの 36px 箱・16px ラベルを含めて「OK」の裁定を得ている**。モックの HTML 自体はセッションの scratchpad にしかない（成果物ではない）。

## 決定1: 段は3サイズ4段。実装はクラスの張り替え

現行（rev 9章 M7 決定6）はサイズが Tailwind 既定のままの5段（`text-xs` 12 / `text-sm` 14 / `text-base` 16 / `text-lg` 18 / `text-2xl` 24）。これを次の**3サイズ4段**に置き換える:

| 段 | サイズ | 行間（既定） | ウェイト | 用途 |
| --- | --- | --- | --- | --- |
| `text-sm` | 14px | 1.3 | 400 | 補助・キーボードヒント・バッジ・ガターの問いラベル列（現 `text-xs` の行き先） |
| `text-base` | 16px | 1.25 | 400 | 本文既定——セル・入力欄・一覧・トースト・ボタンのラベル（現 `text-sm` の行き先） |
| `text-base` ＋ `leading-normal` | 16px | 1.5 | 400 | 複数行の自由記述欄（定義・備考・答えセル）と**キャンバスの折り返しテキスト**（ノード・ステップラベル） |
| `text-xl` | **22px（再定義）** | 1.3 | **500** | 文書タイトル（`FileHeader` のファイル名、現 `text-base` bold）＋アプリ名（現 `text-2xl` bold） |

- **`text-xs`（12px）は廃止。** D11 の「14px を下限とする」に従う。
- **`text-lg`（18px）は閉鎖。** 着手前調査で**実使用 0 件**を確認済み（rev 9章の「画面タイトル」は名目だけだった）。
- **`text-2xl`（24px）は閉鎖。** アプリ名は 22px へ統合する。M7 が `text-xl` を開けなかった理由（「2px 差の段はどちらを使うか決められない」）は 22px と 24px の並存にもそのまま当たるため、**2px 差の段を体系に残さない**。アプリ名のウェイトも bold から 500 に落ちる（文書タイトルと同段・同扱い）。
- **`--text-xl: 22px` は `index.css` の `@theme` で再定義する**（Tailwind 既定は 20px）。22px の出所は D11 の確定スケール（文書タイトル 22px）で、D12 の正規化（14×109/96≒16 と同じ計算系）に由来する。
- **実装方式はクラスの張り替え**（`text-xs`→`text-sm`、`text-sm`→`text-base`、タイトル類→`text-xl`）。トークン値の側を再定義する案（`--text-sm: 16px` 等）は、`sm` と `base` が同値になって段の語彙が壊れるため退けた。`text-*` の使用は着手前調査時点で 36 ファイル 132 箇所（`components/ui/` 含む）。

## 決定2: 行間——既定は詰め、広げる側を明示する

D11 の「密度は行高で稼ぎ、サイズでは稼がない」を、**「詰めた値を既定にし、読ませる欄だけ `leading-normal`（1.5）を明示する」**形で実装する:

- `--text-sm--line-height: 1.3`（現 1.5）／ `--text-base--line-height: 1.25`（現 `text-sm` は 1.65）／ `--text-xl--line-height: 1.3`
- **複数行の自由記述欄とキャンバスの折り返しテキストだけ `leading-normal` を明示する。** 明示が付くのは「読ませる欄」という例外の側であり、密度の既定は詰めた側にある。
- **セクション見出しの 130% は本文の 125% に畳む。** 16px では差が 0.8px しかなく、単行のラベルで視認できない。段を分けない理由として rev 9章に書く。
- ボタンの `--tw-leading: 1.2`（`@layer base`）は据え置き。
- **open-issues の「行の高さをクラスで固定する書き方が2箇所ある——2件目が出たら書き方を決めること」はここで決着する**: 許可する `leading-*` は `leading-none`（バッジ）と `leading-normal`（複数行の欄）の2つだけ（決定9の機械検査）。

## 決定3: セクション見出し（テーブルのカラム名等）

`text-base`（16px）＋ `font-medium` ＋ `tracking-wide` ＋ `text-ink-muted` ＋ `bg-surface-muted`。M21 の決着（沈んだ面・字間・グレー）に **Medium(500) を足すだけ**で、本文と同じ 16px にする。本文との区別はサイズではなく「字間・グレー・面」の3チャネルが運ぶ（D11 の「セクションラベルは字間を広げてグレーに」）。モックで人間が「もう一段大きく」と指摘し 16px で確定した経緯がある（14px 案は却下済み）。

## 決定4: KeyHints の二重減衰を解消する

D11 が名指しする「小さい＋薄いグレー」の二重減衰は、**小ささを残して薄さを外す**: 14px（補助段）のまま `text-ink-muted` → `text-ink`。キー名だけ `ink` にする現行の強弱は、全体が `ink` になることで消える（帯の中の強弱はサイズではなく `KeyHints` の並びが運ぶ）。

## 決定5: 固定高の箱は明示的に1段上げ、padding 由来の箱は自動追従

フォント段に引きずられる寸法は2種類に分かれる:

**明示的に上げるもの（固定高）:**

| 箇所 | 現行 | 変更 |
| --- | --- | --- |
| shadcn `Button` の既定 size（`src/components/ui/button.tsx`） | `h-8`（32px）・`text-sm` | **`h-9`（36px）・`text-base`**。アイコンボタン（Undo/Redo）も帯の中で高さが揃うよう同じ段へ |
| `Badge`（`src/components/badge-styles.ts`） | `text-xs`・`h-[18px]`・`BADGE_BOX_HEIGHT = 18` | **`text-sm`・`h-[20px]`・`BADGE_BOX_HEIGHT = 20`**（見立て。実測で確定）。課題ツリーの `measure.ts` の `BADGE_HEIGHT`（+2）と行高が連動する |
| `ActorRefCell` の `min-h-6`（24px。M22 で追加） | 空名トリガーの高さ担保 | 本文 16px 化後の文字入り実高に合わせて再計算。open-issues の「文字入りとの 2px 残差」の項もここで解消または書き換え |

**自動で追従するもの（padding 由来）:** `buttonBase` を敷く生ボタン（フィルタのチップ・トーストの操作・一覧の行）、`Chip`、セルの入力欄。固定値を持たないので触らない。

**着手前スキャンの義務項目**: 「固定高（`h-*` / `size-*` / `min-h-*`）または px 定数で高さ・幅を持つ、文字の入る箱」を全部洗い出すこと。上の表は設計時点の把握であり、網羅はスキャンが担う。

## 決定6: 方眼 24px は動かさない

複数行段が 16×1.5＝**ちょうど 24px** になり、現行（14×1.65＝23.1px の近似）より方眼と文字行の整合はむしろ良くなる。`--grid-size` は不変、`index.css` の由来コメントだけ新しい計算に書き換える。

## 決定7: ズームは残す——D13 の「100% 固定」を一部修正する

`tauri.conf.json` の `zoomHotkeysEnabled: true` は 2026-08-16 に人間が「アプリの拡大縮小を可能に」として入れたもの（`2fa2785`）で、D13 の「ズーム 100% 固定」と矛盾していた。人間の裁定（2026-08-24）は**残す**:

- **既定は 100%・正規化は基準値側で行う**（D12/D13 の骨子は維持）。ボーダー・方眼は 1px 固定のまま。
- **手動ズーム（Ctrl+±）は逃げ道として残す。** ズーム中の 1px 罫線の滲みは代償として受ける。
- `tauri.conf.json` は触らない。UI ノート D13 に rev.4 訂正を追記し、rev 9章に規範として書く。
- D13 の「将来ズームを提供する場合の制約」（WebView ズームを使う・設定は Git 管理の JSON に保存しない）は生きたまま。`zoomHotkeysEnabled` はまさに WebView ズームであり、倍率はどこにも保存されないので、両制約とも満たしている。

## 決定8: shadcn 生成物の扱い

- **`button.tsx` は改造する**（決定5）。rev 7章のソースコピー方式どおり改造は自由。
- **ドロップダウンのメニュー項目（`dropdown-menu.tsx` の `text-sm`/`text-xs`）は据え置く。** 14px は新体系の補助段の下限内。ただしメニューは参加者名・判断種別というデータ値を出す場所なので、16px のセルの隣で沈むかは**実機確認の項目に入れ、違和感が出たら `text-base` へ上げる**。
- `conventions.test.ts` の `EXCLUDED` の理由コメント「shadcn の生成物。rev 7章『手で整形しない』」は**事実誤り**（M21 の申し送りで確定済み——rev 7章は改造自由と書いている）。除外自体は維持し、理由を「生成物の字面を段の検査に合わせて書き換えない（改造は自由だが、段の規約は自作コードの側に課す）」に直す。

## 決定9: 機械検査

`src/styles/conventions.test.ts` を2点:

1. **段の検査の許可を `text-sm` / `text-base` / `text-xl` の3段に書き換える。** `text-xs`・`text-lg`・`text-2xl` が新たに違反側へ回る（現行の検査は `xl` と `3xl` 以上と任意値を弾く形なので、正規表現の作り直しになる）。
2. **`leading-*` の許可リスト検査を新設する**: 許可は `leading-none` と `leading-normal` の2つだけ。`leading-5` のような数値指定・任意値 `leading-[...]` を弾く。
