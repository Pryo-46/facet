# M7: デザイントークン確定 設計スペック

作成日: 2026-08-09

> **これは実装計画ではない。** M7 で何をどう決めたか、なぜそう決めたかの記録。実装手順は別途 `2026-08-09-m7-design-tokens.md` に書く。
>
> 本スペックが確定させるのは [`overview-rev.md`](../../overview-rev.md) 9章が「色値は仮置き。ドッグフーディング後に決める」として空けていた部分。**9章の構造（役割トークンとパレットの分離、3系統のアクセント、ライト／ダーク独立パレット）は変えない。**

## 目的

1. 仮置きだった色値を確定させ、`src/index.css` に**二層で並存している** shadcn 標準トークン（無彩色のグレー30個）と facet 役割トークンを一本化する
2. **配色を後から気軽に差し替えられる構造**にする。人力での書き換えではなく、AI に指示して差し替える運用を想定する
3. 差し替えた結果が壊れていないことを**ツールが検証する**。rev 3章「網羅性の担保はツールの仕事」をデザインシステム自身に適用する

---

## 決定1: ベースパレットは Morphos の Basalt

[Morphos](https://morphos.ameyanagi.com) の `morphous-basalt` を下敷きにする。玄武岩をモチーフにした、Signal（赤茶）以外すべて彩度 0.07 未満の低彩度パレット。

**facet に向く理由**は3つ。背景 Ash Surface が彩度 0.007 でほぼ無彩なので、方眼紙の上に載る `warning` / `ok` のシグナルと彩度で競合しない（rev 9章「確定要素」で方眼紙背景は採用済み）。Ink が `#171717` とほぼ黒で、密なテキスト UI の本文に耐える。そして紙色として自然で、会議中に長時間見ても疲れない。

### `theme.css` は使わない。`theme.json` の `palette` から拾う

Morphos は shadcn の30トークンを揃えた `theme.css` をドロップイン配布しているが、**これを使ってはならない。**

`light.destructive` が Primary の値で上書きされる生成ミスがあり、Basalt では **destructive が Lichen Green（緑）になっている**。そのまま入れると shadcn の破壊的アクションが緑になる。facet は削除も未定義も `warning` 系で表現する設計（rev 9章）なので、**中核の意味論が静かに壊れる**。

`theme.json` の `palette` 配列には正しい `Signal: Ember Fault #b4533c` が入っている。**そちらから拾う。**

なお同じミスは Sandpiper（destructive がベージュ）・Ibex（destructive がグレー）でも確認しており、Morphos 全体の生成ミスと思われる。**将来ほかのモチーフに差し替えるときも同じ検査が要る。** 決定4の検証テストがこれを機械的に捕まえる。

### 採用しなかったもの

| | 落とした理由 |
| --- | --- |
| **Sandpiper** | 赤緑の識別だけなら最良（Sea Glass が H184 の青緑）だが、背景 `#E9DFC9` が彩度 0.031 で暖色に振れており、方眼紙＋密なテキストには主張が強い |
| **Ibex** | Primary が無彩の Horn Grey で「色を持つのは warning と ok だけ」の構図を作れる点は Basalt より優れる。Border 役割も持つ。**Basalt との差は僅かで、好みで Basalt を採った** |

## 決定2: 役割トークンの割り当て

### `canvas` と `surface` は Morphos と逆にする

Morphos の Basalt は `background`（Ash Surface, L0.961）の上に `card`（Lava Paper, L0.921）を**沈める**構成。facet では**逆にする** — Lava Paper を地（`canvas`）、Ash Surface を面（`surface`）。

理由は方眼紙背景。facet は地の全面にグリッドが敷かれ、その上にファイル一覧・エディタ・モーダルが乗る。**地を沈めて面を浮かせないと、カードの上でもグリッドが透けているように見える。**

### `rule` と `grid` を分ける

rev 9章は罫線を無彩色系の1つとして挙げているが、**facet では2つに割る必要がある。**

| トークン | 用途 | コントラスト要件 |
| --- | --- | --- |
| `grid` | 方眼紙のグリッド線 | **なし**（純粋な装飾。WCAG 1.4.11 の対象外） |
| `rule` | セル境界・入力枠・カードの縁 | **3:1**（情報を伝える非テキスト UI 要素） |

Basalt の `Mineral Line #C4C7BD` は canvas 上で **1.36:1** しか出ないため、`rule` には使えない（当初の割り当てはこれを見落としていた）。`grid` に降ろすと、装飾としてはむしろこの薄さがちょうどよい。`rule` は Mineral Line の色相 H120 を保ったまま L0.600 まで落として導出する。

**ダーク側も同じ問題がある。** Column Grey `#3f4442` は Void Basalt 上で **1.89:1**。L0.500 まで持ち上げて導出する。

### `warning` と `ok` は 4.5:1 まで落として1トークンで済ませる

Ember Fault `#b4533c` は canvas 上 3.92:1、候補 B の Lichen Green（L0.520）は 4.27:1 で、**どちらも面と線には足りるが本文基準（4.5:1）に僅かに足りない。**

「面・線用」と「文字用」で2トークンに割る方法もあるが、**明度をそれぞれ 0.03 ほど落とせば1トークンで両方を満たす。** 色味の変化は目視でほぼ判別できない範囲。実装時に「この色は文字に使ってよいか」を都度考えなくて済む方を採る。

### `ok` は Lichen Green の色相を保ったまま暗くする（候補 B）

Basalt の Primary `Lichen Green #7f9164` は canvas 上 **2.72:1** で、文字にも情報を伝える線にも使えない。明るくすると更に落ちる（L0.70 で 2.08:1）ので、**暗くする以外に道がない。**

3案を実画面のモックで比較して**候補 B（色相 H126 を保ったまま L0.508 まで落とす）を採用**した。苔というより深い草の色になるが、Basalt の色相を離れない。

> **候補 C（Void Basalt の H164.6 から青緑を起こす）は、赤緑の識別では明確に優れていた**（OKLab の ΔE で候補 B の倍以上）。色は後から差し替えられる構造を作るのが M7 の主目的であり、識別性は差し替え時に改めて判断できるため、今回は世界観を優先した。決定4がこの数字を記録し続ける。

### ダークの `ink` は Ash Surface をそのまま使わない

Ash Surface `#f4f2ed` を前景に据えると Void Basalt 上で **16.79:1** 出る。GitHub のダークが約 14:1、VSCode Dark+ が約 11.5:1 であることを踏まえると眩しい。

色相 H88.6 を保ったまま **L0.850（11.89:1）** まで落とす。Basalt の色味は変わらない。

### `Lichen Green` は `ok` 以外に使わない

Morphos は Lichen Green を Primary（ボタン等）に割り当てているが、facet で shadcn の `primary` に流すと**ボタンが緑になり `ok` と衝突する**。`primary` は Ink 系に寄せる。

**facet の画面で強い色を持つのは `warning` と `ok` だけ**という状態を保つ。rev 3章の「未定義」と「決めた上で無効」の型区別を色が運ぶ以上、意味を持たない色が同じ強さで並ぶと区別が薄まる。

## 決定3: 差し替え機構

### `src/styles/palette.css` に色値を隔離する

```
src/styles/palette.css   色値だけ。ライト／ダークの2ブロック。AI が書き換えるのはこの1ファイル
src/index.css            役割名の定義とベーススタイル。色値を持たない
```

**`palette.css` に色以外を書かない。** 半径・余白・フォントを混ぜると「配色の差し替え」が「レイアウトの差し替え」を巻き込む。

差し替えの運用は「Morphos の別モチーフを指定 → その `theme.json` の `palette` から本スペックの割り当て規則で写す → 検証テストを通す」。**変換スクリプトは作らない**（YAGNI。差し替え頻度は低く、規則はこのスペックに書いてある）。

### shadcn の30トークンを同じパレットから導出する

現状 `index.css` は shadcn 標準の無彩色グレー30個と facet 役割トークン9個が**無関係に並存**しており、shadcn 由来のコンポーネント（モーダル・ドロップダウン・トースト）だけが facet の色を纏っていない。

30トークンを役割トークンから導出して一本化する。対応の要点:

| shadcn | facet |
| --- | --- |
| `--background` | `canvas` |
| `--card` / `--popover` | `surface` |
| `--foreground` / `--card-foreground` / `--popover-foreground` | `ink` |
| `--muted-foreground` | `ink-muted` |
| `--border` / `--input` | `rule` |
| `--primary` | `ink`（**Lichen Green を流さない**） |
| `--destructive` | `warning` |
| `--ring` | `ink`（フォーカスリング。**`ok` を当てない** — 「いまフォーカスがある」と「確定した」は別の意味であり、同じ色にすると rev 3章の型区別が薄まる） |

`--chart-*` と `--sidebar-*` は facet が使っていない。**消さずに役割トークンから導出しておく**（shadcn のコンポーネントを後から追加したときに無彩色のまま浮くのを防ぐ）。

## 決定4: 検証テスト

`src/styles/palette.test.ts` を置く。**依存は足さない** — oklch → 線形 sRGB → 相対輝度の変換は数十行で書ける（本スペックの数値はすべてこの計算で出した）。

**テストは `palette.css` をテキストとして読み、`--<name>: oklch(L C H)` を正規表現で拾う。** 色値を TS 側にも持たせて CSS を生成する方式は採らない。正が2箇所に増えるうえ、AI に「このファイルだけ書き換えればよい」と言えなくなる。`palette.css` が色以外を持たない（決定3）ので、この読み取りは壊れない。

CSS が読めなかった・トークンが1つでも欠けていた場合は、**その時点で失敗させる**。値の検証まで到達せずに緑になる経路を作らない。

### 失敗させる項目

ライト・ダークの両方で検証する。

1. `ink` 対 `canvas` ≧ **4.5:1**（本文 AA）
2. `ink-muted` 対 `canvas` ≧ **4.5:1**
3. `rule` 対 `canvas` ≧ **3:1**（情報を伝える非テキスト UI 要素）
4. `warning` 対 `canvas` ≧ **4.5:1**
5. `ok` 対 `canvas` ≧ **4.5:1**
6. `warning-fg` 対 `warning`、`ok-fg` 対 `ok` ≧ **4.5:1**（面の上に載る文字）
7. **`destructive` が `warning` に紐づいていること**（Morphos の生成ミスを踏まないための直接の検査）

`grid` は装飾なので**検証しない**。テストにコメントで理由を残す。

### 赤緑の識別だけは失敗させず、数字を記録する

`warning` と `ok` の OKLab 色差 ΔE を、**標準色覚・P型・D型のそれぞれで計算して出力する**（色覚シミュレーションは Machado 2009 の行列を線形 RGB で適用）。

**このテストは失敗させない。** 採用した候補 B は P型・D型で ΔE が実用域を割るが、色を後から差し替えられる構造を作ることが M7 の主目的であり、ここで失敗にすると差し替えのたびに人間の判断を要求する門番になる。数字を出力に残しておけば、**次に色を触る人がその場で気づく。**

> 失敗させないと決めた以上、この項目は「テストが守るもの」ではなく「テストが見せるもの」である。**この区別を実装時に曖昧にしないこと。**

## スコープ外

- **コンポーネント個別の色の当て直し。** 本スペックはトークンの定義まで。既存コンポーネントは既に役割名で書かれているので（rev の「色値の直書き禁止」が M1 から守られている）、自動的に新しい色になる
- **方眼紙背景の実装そのもの。** `grid` トークンは定義するが、背景を敷く作業は別
- **アプリ内テーマ切替 UI。** 利用者が作者のみの現段階では過剰
- **Morphos からの変換スクリプト**（上述）

## 未解決

- **赤緑の識別性。** 候補 B は P型・D型で ΔE が実用域を割る。色を差し替えるときに候補 C（青緑）を再検討する。`open-issues.md` に載せる
- **`warning` を文字色に使う箇所の実際の見え方。** 4.5:1 は満たすが、未定義セルの「（未定義）」を warning の文字色にするか `ink` のままにして帯と縦棒だけ warning にするかは、実機確認で決める
- **日本語フォントのフォールバックが未指定。** 現行 `--font-sans: 'Geist Variable', sans-serif` で、**Geist は日本語グリフを持たない**ため日本語は環境依存のフォールバックに落ちている（Windows では MS UI Gothic に落ちうる）。rev 9章はフォントもトークン経由と定めており、Basalt の typography 指定も "Noto Sans guidance for Japanese labels" と言っている。**`"Yu Gothic UI", "Hiragino Sans"` をフォールバックに足すだけの小さな変更で効果が大きいので、M7 に含めるかをレビューで判断する**
