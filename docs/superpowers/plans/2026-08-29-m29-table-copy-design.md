# M29 設計スペック — 表形式でコピー（用語集・エラーカタログ・ロジックツリー）

> 2026-08-29 のブレインストーミングで確定した設計。実装計画は別ファイル（`2026-08-29-m29-table-copy.md`）。

## 何を作るか

**用語集・エラーカタログ・ロジックツリーの内容を、Excel・Google スプレッドシートにそのまま貼れる表としてクリップボードへ載せる。** ボタンは「表形式でコピー」1つで、押すと設定ダイアログが開く。

**ファイル出力は作らない。** 表は「今見ているものを別の場所へ持っていく」一時的な動線であって、成果物としてリポジトリに残すものではない。成果物を残す口は既存の「Markdown を書き出す」が持っている。

対象は3ツール。**シーケンスと課題ツリーは規約8 を宣言しない**（後述）。

## 1. モジュール規約8（任意）: 表形式コピー

### なぜ規約5（`OutputProfile`）に乗せないか

規約5 は `toMarkdown: (data: TData) => string` という形で、**Markdown 文字列を返す純関数**と **`.md` 書き出し**を前提にしている。表形式コピーはこの前提を3つ壊す。

- 出力が **TSV と HTML の2つ**で、1本の文字列に収まらない
- **`.md` 書き出しに意味がない**（ファイル出力を作らないと決めた）
- **設定を引数に取る**（No 列・階層番号・親のくり返し・未定義の表示）

押し込むと `toMarkdown` という名前が嘘になる。**規約7（`ClipboardExchange`。Miro 交換）を別枠にしたのと同じ判断**であり、同じ層の任意拡張として規約8 を足す。

**宣言しないツールの規約の点数は増えない。** 額縁はスロットの有無だけを見てボタンの活性を決め、ツールの `type` を名指ししない（規約7 と同じ原則）。

### 契約

```ts
// src/core/table-export.ts

/** 表1枚。**header と rows は同じ列数であること**（列数が崩れると貼り先でセルがずれる） */
export interface Table {
  header: readonly string[]
  rows: readonly (readonly string[])[]
}

/**
 * ダイアログが出す設定。**コアが全部知っている。**
 * モジュールは「自分がどれを使うか」を宣言するだけで、設定の意味も既定値も持たない
 * ——ツールごとに `numbering` の意味が違う、という状態を作らないため
 */
export interface TableOptions {
  /** No 列を付ける */
  numbering: boolean
  /** No の形式。'serial' = 1, 2, 3… / 'path' = 1-1-1 */
  numberStyle: 'serial' | 'path'
  /** 親の文言を毎行くり返す */
  repeatParent: boolean
  /** 未記入を（未定義）と出す */
  showUndefined: boolean
}

export type TableOptionId = keyof TableOptions

/**
 * 読み手の出し分け。**規約5 の `OutputProfile` を流用しない**——あちらは
 * `fileSuffix` と `toMarkdown` を必ず持つが、表形式コピーではどちらも意味がない
 *（ファイル出力を作らない）。持てない値を持たせると、必ず誰かが使う
 */
export interface TableVariant<TData> {
  /** 安定識別子。UI の選択状態・テストが参照する */
  id: string
  /** ダイアログの Select に出す表示名 */
  label: string
  /** 設定 → 表。**副作用を持たない純関数**であること（規約5 と同じ制約） */
  toTable: (data: TData, options: TableOptions) => Table
}

export interface TableExport<TData> {
  /**
   * ダイアログに出す設定項目。**ここに無い設定は既定値で固定される**
   *（用語集に `numberStyle` を出しても階層が無いので選ばせる意味がない）
   */
  options: readonly TableOptionId[]
  /**
   * 読み手ごとの出し分け。**1本ならダイアログに Select を出さない**
   *（`ExportMenu` が「プロファイルが1本のときはドロップダウンを出さない」と
   *  している原則と同じ。選択肢が1つしかない Select は何も選ばせない）
   */
  variants: readonly TableVariant<TData>[]
}
```

エラーカタログの `variants` は **`outputs` と同じく `PROFILES` から導出する**（`module.ts` が既にそうしている）。列セットの定義が増えないよう、`profile.fields` を直に読む。

`ToolModule` に足すスロットは1つ。

```ts
/** 規約8（任意）: 表形式コピー。**持たないツールは書かない** */
tableExport?: TableExport<TData>
```

## 2. コアが持つ部品

| ファイル | 役割 |
| --- | --- |
| `src/core/table-export.ts` | `Table` / `TableOptions` / `TableExport` の型と既定値 |
| `src/core/table-tsv.ts` | `Table` → TSV |
| `src/core/table-html.ts` | `Table` → 素の `<table>` |
| `src/core/table-copy-options.ts` | 設定ストア（アプリを閉じるまで保持） |
| `src/components/TableCopyDialog.tsx` | 設定ダイアログ |

クリップボードへの書き込みは**既存の `copyHtmlToClipboard(html, altText)` をそのまま使う**（`src/fs/clipboard.ts`）。HTML とプレーンテキストを同時に載せる経路は Miro 交換で既に通っている。`altText` に TSV を渡すことで、Excel・スプレッドシートは HTML を、メモ帳・Slack・AI の入力欄は TSV を受け取る。

### エスケープ

**セルの中身は書き手を信用せずエスケープする。** `markdown-table.ts` の JSDoc が述べている危険（自由記述欄に Windows パス・正規表現・外部が書いた複数行の値が入り、表が途中で割れて1件まるごと読めなくなる）は形式が変わっても消えない。

**`escapeCell` は流用できない**——あれは `|` を逃がす Markdown の表専用の規則で、TSV にも HTML にも合わない。**規則を2つ持つことになるが、それぞれの形式が要求するものが違うので統合できない。** 統合すべきなのは「エスケープするという判断」であって、置換表ではない。

- **TSV**: 改行・タブ・`"` のいずれかを含むセルだけ `"` で囲み、セル内の `"` は `""` に倍化する（RFC 4180 の規則。Excel・Google スプレッドシートともこの形を1セルとして読む）。**含まないセルは囲まない**——素のままの方が他所に貼ったときに読みやすい
- **HTML**: `&` `<` `>` を実体参照へ。**`&` を先に処理する**（順序を逆にすると、実体参照で入れた `&` まで二重にエスケープされる。`escapeCell` がバックスラッシュを先に処理しているのと同じ罠）。改行は `<br>`

### HTML は素の `<table>`

罫線・背景色・フォント指定を一切付けない。**装飾を付けると「書式なしで貼りたい」に応えられなくなる**——貼り先の書式に馴染ませるのが表形式コピーの目的である。`<thead>` / `<tbody>` は付ける（見出し行を貼り先が見出しとして扱えるようにするため）。

## 3. ダイアログ

ツールバーには**平ボタン1つ「表形式でコピー」**を `ExportMenu` の隣に足す。ドロップダウンにはしない——**エラーカタログのプロファイル選択もダイアログの中の Select に入れる**。設定が4つ並ぶ画面で、プロファイルだけ手前のドロップダウンにあるのは動線が割れる。

```
┌─ 表形式でコピー ────────────────────┐
│ ⚠ このファイルには整合性エラーが 2 件  │   ← 赤があるときだけ
│   あります。                          │
│   ・ID が重複しています: error_xxx     │
│   ・…                                 │
│   このまま出力すると、指摘のある箇所も │
│   そのまま出力に含まれます。           │
│                                       │
│ 読み手  [サポート向け ▾]              │   ← エラーカタログのみ・2本以上のとき
│                                       │
│ ☑ No 列を付ける                       │   ← 全ツール
│   ◉ 階層番号（1-1-1）                 │   ← ロジックツリーのみ
│   ○ 通し番号（1, 2, 3…）              │      No 列オフなら不活性
│ ☐ 親の文言を毎行くり返す               │   ← ロジックツリーのみ
│ ☑ 未記入を（未定義）と出す             │   ← 全ツール
│                                       │
│                 [キャンセル] [コピー]  │
└───────────────────────────────────────┘
```

**既定値**: No 列オン／階層番号／親は先頭行だけ／未記入は（未定義）を出す。

**開いている間は `KeyContext.modalOpen` を true にすること**（rev 10章の境界規則。Esc をダイアログとエディタで取り合わないため。`ConfirmDialog` / `ChoiceDialog` と同じ配線）。

**`ConfirmDialog` / `ChoiceDialog` は流用できない**——どちらも二択専用で、本文に入力要素を持てない。新規コンポーネントになる。

### 設定の寿命

**アプリを閉じるまで覚え、ファイル切替・ツール切替をまたぐ。** 会議中に何度も貼るので毎回選び直すのは煩わしい。列幅ストア（`src/modules/glossary/column-widths.ts`）と同じ作りで、`src/core/table-copy-options.ts` にモジュールスコープのストアを置く。

**`settings.json` への永続化はしない。** 現在 `saveLastProjectDir` がファイルを丸ごと上書きしているので（`src/fs/settings-fs.ts`）、設定を足すには読んで書き戻す形へ直す必要があり、直し損ねると**直近フォルダの復元が壊れる**。得られるもの（再起動をまたいで好みが残る）に対して危険が大きい。

**モジュールスコープの可変状態はテスト間で漏れる。** DOM テストの `beforeEach` で `reset()` を呼ぶこと（列幅ストアと同じ注意）。

### 赤があるときの確認

**ダイアログを2枚重ねない。** 既に開いている設定ダイアログの上部に警告を出し、[コピー] を押すこと自体を確認とみなす。

Markdown コピーが `guardIssues` で別の `ConfirmDialog` を挟んでいるのとは動線が違うが、**あちらは設定ダイアログを持たない**ので確認を挟む場所が他に無かった、という差である。

**文面は `exportConfirmDescription`（`app-controller.ts:782`）をそのまま再利用する。** 件数 ＋ 指摘の先頭数件 ＋ 「出力に何が起きるか」の1文、という組み立てを2つ持たない。

**ただし今回の3ツールはいずれも `describeIssueEffect` を実装していない**——実装しているのはシーケンスだけである（`sequence/module.ts:31`）。したがって効果の文は汎用文（「このまま出力すると、指摘のある箇所もそのまま出力に含まれます。」）になる。**ツール固有の文面を今回足すことはしない**（規約5 の任意スロットであり、足すなら Markdown 側と揃って足すべきもので、表形式コピーの都合で片方だけ埋めると出力によって説明が変わる）。

`exportConfirmDescription` は今 `OutputProfile` を引数に取っているが、**`describeIssueEffect` の1つしか使っていない。** 表形式コピーには `OutputProfile` が無い（`TableVariant` は `toMarkdown` も `fileSuffix` も持たない）ので、**引数を `describeIssueEffect: ((issues) => string) | undefined` へ狭める**。呼び出し側2箇所を直すだけで、`guardIssues` の振る舞いは変わらない。

## 4. 各ツールの表

`variants` は**エラーカタログだけが2本**（サポート向け・開発向け）で、用語集とロジックツリーは1本。1本のツールではダイアログに「読み手」の Select を出さない。

### 用語集

列は**画面のエディタに出ている並びそのまま**。

| No | 用語 | 種別 | 定義 | 別名 | 備考 |

- **種別は列に戻る。** Markdown 出力は `###` のグループ見出しに逃がして列から落としているが、表では見出しが使えない。グループごとに表を分けて空行で区切ると、スプレッドシートに貼ったときに1つの表にならない
- 別名は読点で連ねる（Markdown と同じ。1行1件で持っているものを表に収めるときだけ連ねる）
- `numberStyle` は宣言しない（階層が無いので通し番号のみ）
- `repeatParent` は宣言しない

### エラーカタログ

列は**プロファイルの `fields` そのまま**（＝画面の列）。

- サポート向け: No / エラー名 / 発生条件 / **解決レベル** / 原因（サポート向け） / 利用者の対応 / サポートの対応 / エンジニアの対応
- 開発向け: 上記に 原因（仕様） と 備考 を加えたもの

**`markdownFields()` を使わない。** あれは `resolutionLevel` を落とす関数で、落とす理由は「グルーピング軸が h3 見出しになるから」（`profiles.ts` の JSDoc）。表に見出しは無いので、落とす理由も無い。**`profile.fields` をそのまま使う**——プロファイルの JSDoc が「`fields` に `resolutionLevel` を含めるのは画面には列として出すため」と述べている通り、表は画面と同じ側にいる。

`numberStyle` / `repeatParent` は宣言しない。

### ロジックツリー

列は `[No] / 第1階層 / 第2階層 / …`。**列数は木の最大深さで決まる。** 行は**葉ノードごとに1行**。

```
No       第1階層          第2階層          第3階層
1-1-1    売上が下がった    客数が減った      新規が減った
1-1-2                                       離脱が増えた
1-2-1                     単価が下がった    値引きが増えた
1-3                       （未定義）
```

- **中間ノードは自分の行を持たない。** したがって階層番号（`numberStyle: 'path'`）に出るのは葉のパスだけで、中間ノードの番号はどこにも出ない。番号は葉を指す識別子として使う
- `repeatParent` がオンなら、親の文言をその配下の全行にくり返す（並べ替え・フィルタ・ピボットが行単位で成立する）。オフなら先頭行だけ（貼ったまま木の形が目で追える）
- 空の `text` は `showUndefined` に従う
- **走査順は既存の Markdown 出力と同じ**（`buildTree` の行きがけ順）。同じデータから2つの出力が違う順で出るのは、後から必ず疑われる

## 5. 絞り込みの追従（既存の振る舞いの変更）

**今回いちばん侵襲的な変更。**

| 口 | 範囲 | 変更 |
| --- | --- | --- |
| 表形式でコピー | 絞り込み後 | 新規 |
| Markdown をコピー | 絞り込み後 | **振る舞いを変える** |
| Markdown を書き出す | 全件 | 変えない |

**書き出しだけ全件に残すのは、口の性質が違うから。** クリップボードは「今見ているものを別の場所へ持っていく」一時的な動線だが、ファイル書き出しは「成果物を残す」永続的な動線であり、絞り込んだままの `.md` は**一見完全な成果物の顔で Git に残る**。後から見て「絞り込み中だった」とは分からない。

### 持ち上げ方

絞り込み状態は今エディタ内の `useState` に閉じている（`GlossaryEditor.tsx:77` の `filter`）。額縁から見えないため、既存の Markdown コピーは絞り込みを無視して全件を出している。

**エディタが「画面に出ている行の ID 集合」を額縁へ報告し、額縁はそれを出力関数へそのまま渡す。**

```ts
// src/core/table-export.ts
/**
 * 画面に出ている行の ID 集合。**null / undefined は「絞り込みなし＝全件」。**
 * 出力側がこれで行を間引く
 */
export type VisibleRows = ReadonlySet<string> | null

// EditorProps に追加
/**
 * 絞り込みの状態を額縁へ知らせる。**絞り込みが無い状態では ids に null を渡す。**
 * `total` はファイル内の全行数（トーストの「42 件中 3 件」に使う）。
 * 絞り込みを持たないエディタは呼ばなくてよい（額縁は全件・件数不明として扱う）
 */
onVisibleIds?: (ids: VisibleRows, total: number) => void

// OutputProfile / TableVariant の署名に任意引数を1つ足す
toMarkdown: (data: TData, visible?: VisibleRows) => string
toTable: (data: TData, options: TableOptions, visible?: VisibleRows) => Table
```

**額縁がデータを先に間引いてはならない。** エラーカタログの **No はデータ配列の位置**（`index + 1`）で、画面も絞り込み中に元の No を出している（`ErrorCatalogEditor.tsx:453`）。額縁が間引いてから `toMarkdown` に渡すと **No が 1 から振り直され、画面の No と出力の No が食い違う**——`error-catalog/markdown.ts` の No の JSDoc が「口頭で指すための目印として使えない」と警告している、まさにその壊れ方になる。**間引きと採番を同じ場所（出力関数）に置く**ことでしか避けられない。

**引数は任意にする。** 絞り込みを持たないツール（ロジックツリー・シーケンス・課題ツリー）の出力関数は**1文字も変えなくてよい**——受け取らなければ無視される。実際に手を入れるのは用語集とエラーカタログの `toMarkdown`、および今回新設する3本の `toTable` だけ。

**ID で切るのが要点である。** 報告は `useEffect` を経由するので1フレーム古くなりうる。**index（添字）で切ると、行を削除した直後の古い添字が別の行を指し、間違った内容が黙って出る。** ID なら、消えた ID は一致せず落ちるだけで、**間違った行の内容が出ることは原理的にない**（最悪でも行が1本欠ける）。ID が不変であることは rev 5章の ID 規約が保証している。

**`filter` state を App まで持ち上げる案は採らない。** タイミングの隙が原理的に無いという利点はあるが、検索欄と種別チップがエディタのツールバー内にあるため、エディタ2本の状態と props を組み替える改修になる。上の劣化のしかた（内容は絶対に化けない）で受け止められる危険に対して、改修が大きすぎる。

### トーストで件数を出す

**絞り込んだまま貼って一部しか渡っていない事故**に気づけるよう、コピー完了のトーストを件数入りに変える。

- 絞り込みあり: 「表をクリップボードにコピーしました（42 件中 3 件）」
- 絞り込みなし: 「表をクリップボードにコピーしました（42 件）」
- **件数を報告しないツール**（ロジックツリー）: 「表をクリップボードにコピーしました」——件数を付けない。行は葉の数であって「ノード 12 件」ではなく、数え方を説明せずに数字を出すと誤読される

Markdown コピーのトーストも同じ形に揃える（振る舞いを変える以上、変わったことが見えなければならない）。

**No は絞り込んでも振り直さない。** エラーカタログの表・Markdown ともデータ配列の位置（`index + 1`）を出す。用語集の表の No も同じ規則にする（画面に No 列は無いが、絞り込み中に番号が飛ぶことで「これは全件ではない」が読み取れる）。

## 6. テスト

- **TSV のエスケープ** — 改行・タブ・`"` を含むセル、`"` の倍化、囲まないセル
- **HTML のエスケープ** — `&` `<` `>` の順序、改行の `<br>`
- **各モジュールの `toTable`** — 用語集（種別が列にあること・別名の連結）／エラーカタログ（`resolutionLevel` が落ちないこと・2プロファイル）／ロジックツリー（深さ・空文言・`repeatParent` の両値・`numberStyle` の両値・単一ノード・多重ルート）
- **`TableCopyDialog` の DOM テスト** — ツールごとに項目が出し入れされること／No 列オフで形式が不活性になること／赤があるとき警告が出ること
- **絞り込み追従の App レベル DOM テスト** — 絞り込み中の表コピーと Markdown コピーが絞り込み後の件数になり、Markdown 書き出しが全件のままであること
- **設定ストアの `reset()`** — `beforeEach` で呼ぶこと（漏れると他のテストが落ちる）

## 7. スコープ外

- **ファイル出力**（`.tsv` / `.csv` の書き出し）
- **CSV**（TSV で用が足りる。区切り文字を選ばせる設定は作らない）
- **シーケンス・課題ツリーの表形式コピー**（規約8 を宣言しない）
- **`settings.json` への設定の永続化**（§3 の理由）
- **絞り込み状態の App への持ち上げ**（§5 の理由。ID 報告で代替する）
