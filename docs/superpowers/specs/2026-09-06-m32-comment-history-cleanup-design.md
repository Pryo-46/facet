# M32 コードのコメントから経緯を落とす 設計スペック

作成: 2026-09-06

## 1. 目的

ソースコードのコメントは Claude だけが読む。いまのコメントは「なぜこうなっているか」と「いつ・誰が・以前はどうだったか」が混ざっており、後者は git にあるので不要である。本マイルストーンは後者だけを削り、再び混ざらない規則を `CLAUDE.md` に置く。挙動は変えない。

## 2. 現状

| 対象（非テストの TS/TSX） | 値 |
| --- | --- |
| ソース行 | 22,320 |
| コメント行 | 7,452（33%） |
| コメントの文字数 | 262,645（コードは 499,584。日本語はトークン密度が高く、トークンではコメントがコードを上回る） |
| マイルストーン番号を含む行（テスト名を含む、全対象） | 547 |

Claude の作業への影響は3つある。ファイルを開くたびにコード本体より多くのトークンを読む。識別子の Grep でコメント行が過半を占め、参照箇所を追う精度が落ちる。周囲のコメントの文体を真似るので、経緯付きコメントが経緯付きコメントを増やす。

`CLAUDE.md` は文書に「現在形で書く。経緯・マイルストーン番号を書かない」を定めているが、コードのコメントは対象外で、抑止が働いていない。

## 3. 方針

**削る**（git に任せる）

- マイルストーン番号（`M5`・`issue-tree-m3` 等）と、それだけを出典にする括弧
- 出典が人であること（「レビュー指摘」「依頼者の指示」「人間が実機を触って指摘した」「実機修正」）
- 変更前の状態（「以前は〜だった」「当初は〜していた」「M24 より前は〜」「320 → 360 に伸ばした」）
- 「〜で確定」「申し送り」「フォローアップ」「残件から落とした」の記録

**残す**（いま従う理由と罠）

- いまの値・構造の理由（「固定。導出しない。一番長い行に合わせると木が階段状に見える」）
- 踏むと壊れる罠（「`disabled` 属性を使うとツールチップが二度と出ない」）
- 不変条件と、それを守る場所（「変更前の一覧から引く。ホストの値は表示の複製で判断に使わない」）
- 参照先（`rev N章`・design-notes の論点番号・ファイル名・テスト名）

**書き換え方**

- 罠は失敗のエピソードでなく、現在形の条件文で書く。「当初 `elapsed >= 0` を条件にしていたためにこの尾を取り逃がしていた」は「`elapsed >= 0` を条件にするとこの尾を取り逃がす」にする
- 「以前は A だったが今は B」は B の理由だけ残す。A を知る必要があれば `git log` で辿れる
- テストの名前も同じ規則に従う。「`copyTable（M29）`」は「`copyTable`」、「`M4 の罠`」は罠の中身に置き換える
- 削って残った文が理由も罠も言っていなければ、コメントごと消す

## 4. 検証

- コメントとテスト名以外を変えないことを機械で確かめる。対象ファイルを `origin/main` と比べ、コメントを剥がしたうえで残る行の列が一致すること（テスト名の行だけは違ってよい）
- マイルストーン番号と出典語がコメントとテスト名に残っていないことを機械で確かめる（HARD 一覧が 0 行）
- `npm test`・`npx tsc -b`・`npm run lint`・`cargo test` が緑
- コメントの文字数の減少を報告する

## 5. 対象外

- `docs/`・`*.md`・`sample-project/`・`schemas/`。文書の規則は `CLAUDE.md` に既にある
- `src/core/reading-guide.md` と `.claude/skills/*/SKILL.md`。利用者へ配布する文書で、コメントではない
- 二倍ダッシュ（`——`）や太字の整理。文を書き換える箇所で自然に直る分だけでよい
- コメントの新規追加や、理由の説明が足りない箇所の補強
