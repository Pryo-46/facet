# アプリアイコン デザインスペック

作成日: 2026-08-14。ビジュアルブレインストーミング（切子面4案 → D系6案 → 面数×地4案 → 配色6案 → 蒼玉3案 → 枠線2案）を経て確定。

## コンセプト

アイコンの面そのものを**7つの切子面（facet）**で割り、**右下の一面だけ Ember の橙が灯る**。

- 「facet ＝ 多面的な仕様を面ごとに切り出して見る」という名前の直訳
- 灯る一面は「未定義が物理的に見える」（rev 3章）の warning 意味論を継ぐ
- 配色は深青サファイア。アプリのパレット（玄武岩系）とは独立に、補色関係で Ember が最もよく灯る色として選定した

## 成果物

`src-tauri/icons/` の既存ファイルを**同名で**全差し替え（`tauri.conf.json` は変更不要）。

| 対象 | 形 |
| --- | --- |
| マスター SVG（`src-tauri/icons/icon.svg` として新規コミット） | フルブリード。**色は sRGB hex に変換して焼き込む**（librsvg / resvg は oklch 非対応のため。oklch 値は本スペックが正） |
| Windows: `icon.ico`, `Square*Logo.png`, `32x32.png`, `128x128.png`, `128x128@2x.png`, `StoreLogo.png`, `icon.png` | フルブリード |
| macOS: `icon.icns` | **Apple 標準余白入り** — 1024px キャンバス中央に 80%（819px 相当）の角丸タイル、周囲は透明 |

## 生成方式

公式 `tauri icon` CLI を2回:

1. フルブリード 1024px PNG → `tauri icon` で全形式を生成
2. 余白入り 1024px PNG → 別ディレクトリに生成し、`icon.icns` **だけ**を採用して上書き

`tauri icon` は SVG を直接受け取れる（内部でラスタライズする）ため、中間 PNG や追加のレンダラは不要。新規の恒久依存・自作スクリプトは追加しない（一発作業。再生成の手順はマスター SVG と本スペックがあれば再現できる）。

oklch → sRGB hex の変換結果（マスター SVG に焼き込む値）:
左上 `#5174a0` ／ 上 `#799bc3` ／ 左 `#385681` ／ 中央 `#6689b3` ／ **Ember `#dd6d49`** ／ 左下 `#2c4267` ／ 下 `#446590` ／ 境界線 `#070b14`

## 検証

- 生成後、`icon.icns` に余白が入っていること／その他がフルブリードであることを目視確認（`sips -g pixelWidth` とプレビューで）
- `npm run tauri dev` を起動し、Dock（macOS）にアイコンが出ることを確認
- Windows 側は本マイルストーンでは目視確認しない（CI もアイコンを検査しない）。ico が生成されていることのみ確認

## 決定の記録（ブレインストーミングでの選択）

1. コンセプト: 「切子面・多面体」＋「未定義の可視化」の合成（文字ベース案・ツールの束案は不採用）
2. シルエット: 結晶の「絵」ではなく全面ファセット（D）。面数は 7（5面の大割りより結晶らしさが残る方を選択）
3. 配色: 蒼玉（F5）。玄武岩・溶岩・苔・琥珀・緑アクセント案は不採用。青はアプリ内パレットに存在しない色だが、アイコンは独立した成果物として許容
4. 青の深さ: 深青（G2）。淡青・白青は不採用
5. 枠線: 外周リムなし、内部境界線は太め 3px（H1。細線 1.8px は小サイズで消えるため不採用）
6. macOS 余白: あり（Apple 標準）。Windows はフルブリード
