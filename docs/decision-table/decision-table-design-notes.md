# デシジョンテーブルエディタ 設計ノート

条件の組み合わせで結果が決まる仕様を、全組み合わせを展開した表として扱うツールの設計判断をまとめる。データ形式の正は [`../../schemas/decision-table.schema.json`](../../schemas/decision-table.schema.json)。

## データモデル

`conditions`（`{ id, name, values[] }`）と `outcomes`（`{ id, name, choices[] }`）だけが ID を持つ。行（`rows`）は導出物なので ID を持たず、先頭を `#1` とする位置で指す。

行は値のラベルを直接持つ。`values[i]` は `conditions[i].values` のラベルそのもの、`results[j]` は `outcomes[j].choices` のラベルか空文字で、**行だけを見て内容が読める**（条件・結果の定義を突き合わせなくても値がわかる）。

`name` にも値ラベルにも `minLength` を課さない。空文字は「未記入」を表す正当な値である。

## 行の導出

行の集合は `conditions` の値の直積である。並び順は配列順にネストしたループで、左端の条件が最もゆっくり回る。

条件が0本なら行も0本にする。空タプル1本を出しても、条件を立てる前の表には人が埋めるものが無い。

条件を1つ足すと、値を1つだけ持つ空の条件が増える。値の本数を2以上にすると、決めていない値の形を決めたように見える。

結果を1つ足すと、選択肢を持たない空の結果が増える。

定義部（`conditions` の追加・削除・並び替え・値の増減）を触るたび、アプリが行を直積へ整え直す。引き継ぎは**旧の直積での位置**で行い、ラベルでは行わない——同じラベルが2件あるファイルでは、ラベルだけでは行を一意に指せない。

新しい条件は制約を置かないので、旧の1行が複数行へ複製される。消した条件は複数の旧行を1行へまとめるので、結果が食い違えば空欄に落ちる。

新しい値は引き継ぐ元が無いので、空から始まる。

## 欠落

結果セルの空文字は欠落（黄）である。ただし `impossible: true` の行の結果セルは数えない——起こりえないと決めた組み合わせに結果を求めると、永遠に埋まらない欠落が残る。

条件名・値ラベル・結果名・選択肢ラベルの空文字も欠落である。帯のチップは2つ、結果セルの「未記入」と名前・ラベルの「名前なし」に分かれる。

## 整合性検証

自ファイルで完結する検証を持つ。

- `duplicate-id` — `conditions` どうし・`outcomes` どうしの ID 重複
- `duplicate-name` — 条件名どうし・結果名どうしの重複。NFKC 正規化と英字の大小同一視で判定し、空文字は対象外
- `duplicate-value` — 1つの条件の中の値ラベルの重複
- `duplicate-choice` — 1つの結果の中の選択肢ラベルの重複
- `row-length` — `values` の長さが `conditions` と違う、または `results` の長さが `outcomes` と違う
- `unknown-value` — `values[i]` が `conditions[i].values` に無い、または `results[j]` が `outcomes[j].choices` に無い。空文字は対象外
- `row-set` — 行の集合が直積と一致しない。欠け・余り・順序違いを1件でまとめて出す

スキーマは `values`・`choices` の重複を `uniqueItems` で拒否しない。打ち終わる前の自動保存がレベル1違反（開けないファイル）を作らないようにするためで、重複の指摘は上の `duplicate-value` / `duplicate-choice` に委ねる。

## キーボード

定義部（条件の一覧と結果の一覧）は `family: 'tree'`。条件と値は親子である。

- `Enter` — 同じ一覧に行を1つ足す（条件なら条件、結果なら結果）
- `Tab` — 名前セルからは1つ目のラベルへ、ラベルの欄からは次のラベルへ移る。移動先が無ければ生やして移る
- `←` — キャレットが先頭にあるとき、ラベルの欄から名前セルへ移る。名前セルには親が無いので何も起きない
- `→` — キャレットが末尾にあるとき、名前セルから1つ目のラベルへ移る。`Tab` と違い、移動先が無ければ何もしない
- `$alt+↑↓` — 行の並び替え。ラベルの欄では効かない
- 空欄で `Backspace` — 名前セルなら行を消し、ラベルの欄ならそのラベルを消す。消したあとは一つ手前の欄へ移り、先頭を消したときは名前セルへ戻る

表本体は `family: 'grid'`。

- `↑↓←→` — セルの移動だけ。値を書き換えない
- `Enter` / `Space` — 結果セルのドロップダウンを開く。値の変更は開いたときだけに限る
- `Tab` — 次の列へ移る
- 主修飾キー＋`Enter`（`toggle-item-state`）と、表の右端のボタン — `impossible` の入り切り。この操作のために `Command` の語彙は増やさない

## 表の見せ方

セルの面は、無効・欠落・フォーカスのある行・条件列の順に強い。

列のグループの境界（条件と結果の間、結果と右端のボタンの間）は強い罫線にする。グループ内は弱い罫線にする。

フォーカスのある行に面を敷く。画面共有で行を指すための表示であり、データには持たない。

結果セルのドロップダウンを開いている間も、その行の面を残す。

No セルと条件セルはクリックでその行へ移る。編集はできない。

## 絞り込みとまとめて入力

表の列ごとに絞り込みを持つ。条件列は値、結果列は選択肢と「未記入」を並べ、列の中は OR、列どうしは AND で効く。

`起こりえない` の行を出すかは表全体のチェックボックス1つが持ち、既定は出す。

絞り込みの状態はデータに持たない。見ている範囲は人ごと・その場ごとに変わるもので、ファイルに残すと他の人の表示まで動かす。

鍵は条件・結果の `id` である。位置で持つと、並び替えたときに別の列の絞り込みを引き継ぐ。

**絞り込みの結果が、そのまままとめて入力の適用先になる。** 対象を指す操作を2つ持つと、絞り込んだ表を見ながら別の条件へ書き込む事故が起きる。

まとめて入力は上書きを常に行い、確認を挟まない。Undo で1手として戻せるので、確認は打鍵を増やすだけになる。

通知に出す行数は、ボタンの対象行数と分母が違う——ボタンは出ている行を数え、通知はそのうち値が変わった行を数える。

表示中と全体の行数は、絞り込んでいない間も出す。数が出たり消えたりすると、絞り込みが効いているかを数の有無で読む癖が付く。

絞り込んでも No は振り直さない。No は行の呼び名（`#N`）であり、絞り込みで変わると会話の中で行を指せない。

絞り込みは、いまの条件・結果に合わせて描画のたびに刈り込む。消えた列の鍵・その列に無いラベル・列の全ラベルを覆う選択を落とし、絞り込んでいない形へ戻す。

人が全部のチェックを外した空の選択は残す。空は「1行も出さない」指定であり、刈り込みでラベルが消えて空になった状態とは別である。

値ラベルの書き換えには、書き換えを呼ぶ側が絞り込みを追従させる。旧ラベルと新ラベルの対応を知るのは呼ぶ側だけで、刈り込みからはラベルが1つ消えて1つ増えたようにしか読めない。

絞り込みで隠れた行の面は捨てる。行ごと消えたセルからは blur もメニューを閉じる通知も届かない。

欠落の帯から飛ぶときは、飛び先が隠れていれば絞り込みを外す。帯は全行を数えるので、表示中の行だけを巡ると数とジャンプ先が食い違う。

額縁への報告の鍵は、値の組み合わせから作る。報告は1フレーム古くなりうるので、添字を鍵にすると、直積が縮んだとき同じ添字が別の組み合わせを指す。

## 大きさの上限

行数の上限は 1024（`MAX_ROWS`）である。

- 歯止めは値を足す側だけに置く。値を1つ足すと、その条件の値の本数の比で直積が膨らむ
- 値1つの条件を足しても行は増えないので、条件の追加は直積が上限内なら止めない。外から開いたファイルの直積が既に上限を超えているときは、条件の追加も止まる
- どの条件にも値を足せなくなったとき、その旨を画面に出す
